## 1. 平台概述

AgentOps 是面向研发团队的企业级 Agent 能力底座与治理平台。它帮助业务团队通过配置快速构建 Agent，将 MCP / Skill / Prompt 等沉淀为可复用资产，并通过统一评测体系保证质量可量化、可回归、可规模化。

**定位一句话**：研发团队的 Agent 能力中台——用配置出 Agent，把工具与提示词沉淀为资产，用评测把「能跑」升级到「敢规模化跑」。

AgentOps 是 **Control Plane（管理面）**：负责鉴权、工作空间、资产版本、会话元数据、评测与对外 Open API；**真正执行 Agent** 由运行时与外部依赖（模型、OpenSandbox、MCP 等）完成，前端只调用 AgentOps 后端。

### 1.1 核心模块

| 分类 | 模块 | 说明 |
|------|------|------|
| 基础 | 工作空间 | 资源归属与协作边界，多空间隔离 |
| 核心 | Agent 管理 | 配置模式 / A2A 模式；版本化；对外秘钥与 API 文档 |
| 资产 | Skill 管理 | DIRECT 在线编辑 / UPLOAD ZIP；发布检查与版本 |
| 资产 | 工具管理 | MCP / FunctionCall，多种创建模式 |
| 资产 | Prompt 中心 | 提示词模板，`{{变量名}}` 占位 |
| 资产 | 模型管理 | 空间模型 + 系统模型；草稿→启用→禁用 |
| 资产 | 沙箱管理 | 对接 OpenSandbox；草稿→初始化→在线→下线 |
| 运行 | 调试台 | 多轮对话、SSE 流式、步骤链可视化 |
| 质量 | 评测体系 | Skill / Agent 评测、种子用例 |
| 管理 | 权限 / 用户 | 空间角色 + 平台角色；平台用户账号 |

### 1.2 页面导航

登录后进入工作台。左侧导航按模块分组，顶栏提供**工作空间切换**与用户菜单。

> **权限过滤**：无权限的菜单与按钮不展示（非置灰）。若缺少能力，请联系空间管理员或平台管理员授权。

| 导航分组 | 典型页面 | 权限提示 |
|----------|----------|----------|
| 智能体中心 | Agent 管理、Agent 调试 | `agent:*` / `debug_console:access` |
| Skill Hub | Skill 管理、Skill 评测 | `skill:*` / 评测相关权限 |
| 资产 | 工具 / Prompt / 模型 / 沙箱 | 对应 `tool:*` / `prompt:*` / `model:*` / `sandbox:*` |
| 权限与设置 | 角色管理 | `role_manage:*` 等 |
| 门户级 | 工作空间、系统模型、用户管理 | 平台级权限 |

## 2. 登录与快速入门

### 2.1 登录

1. 打开平台登录页 `/login`。
2. 输入**用户名**与**密码**登录（平台本地账号体系）。
3. 登录成功后进入工作台；已登录再访问 `/login` 会跳转工作台。

> 账号由平台管理员在「用户管理」中创建。首次使用请向管理员索取账号，或确认是否已完成初始化管理员引导。

若无权限访问某页，会看到 403；页面不存在为 404；服务异常为 500。

### 2.2 新用户 15 分钟路径

1. **确认工作空间**  
   顶栏查看当前空间；可到「工作空间」创建/加入空间。切换空间后，Agent / Skill / 工具等列表会刷新为当前空间资产。

2. **确认模型已启用**  
   进入「模型管理」，至少启用一个模型（或使用已启用的系统模型）。Agent 配置只引用已启用模型，无需手填密钥。

3. **（可选）准备 Skill / 工具 / 沙箱**  
   需要特定能力时，先在对应模块创建并发布；沙箱需提交并变为**在线**后才能挂到 Agent。

4. **创建 Agent（配置模式）**  
   Agent 管理 → 新建 → 配置模式：填写基本信息、选模型、挂载 Skill/工具/沙箱 → 保存/发布。

5. **调试台验证**  
   Agent 调试 → 选择执行 Agent → 输入测试内容 → 观察流式回复与步骤链。

6. **（可选）评测**  
   Skill 评测或 Agent 详情进入评测，做人工/自动评估。

7. **对外接入**  
   Agent 详情 →「API 信息」查看 cURL；「秘钥管理」创建 `ak-` 密钥发给业务方。

## 3. 工作空间管理

工作空间是资产归属边界与协作容器。一个用户可归属多个空间；切换空间即切换资产视图。

### 3.1 创建空间

工作台 →「工作空间」→「新建空间」：

- 名称：必填，≤64 字符，可见范围内唯一  
- 描述：可选  
- 可添加初始成员  
- 创建人自动成为管理员  

### 3.2 成员管理

空间卡片 →「编辑」：

- 添加成员（按工号等搜索），设为管理员或成员  
- 提升 / 降级 / 移除  
- 至少保留 1 名管理员；仅剩一名管理员时，降级与移除会受限  

### 3.3 切换空间

顶栏空间切换器选择目标空间；选中状态会持久化，下次登录默认载入上次空间。

### 3.4 删除空间

仅管理员可删。条件：

- 空间内无资产（Agent / Skill / 工具等为 0）  
- 确认弹窗中输入完整确认词（如 `我确认删除 <空间名> 空间`）  

删除为逻辑删除，记录保留但不再可见。

## 4. Agent 管理

| 创建方式 | 说明 | 平台侧 |
|--------|------|--------|
| 配置模式 | 单页表单配置 Agent，挂载 Skill / 工具 / 沙箱等 | 可编辑、发布、下线 |
| A2A 模式 | 经 Nacos 发现并同步外部 A2A Agent | 只读；可手动重新同步 |

### 4.1 创建 Agent（配置模式）

**分区 1 — 基本信息**

- 名称（同空间唯一）、描述  
- 系统提示词（可从 Prompt 中心选取；支持 `{{变量}}`）  
- 用户提示词、温度（0.0～2.0，默认 0.7）  

**分区 2 — 关联模型**

- 下拉选择已启用模型（空间模型或系统模型）  
- Plan 模式：默认关闭；开启后运行时启用规划能力  

**分区 3 — 工具与上下文（Tab）**

| Tab | 说明 |
|-----|------|
| Skills | 多选已发布 Skill |
| 工具 | 多选已发布工具（MCP / FC） |
| 沙箱 | 单选「在线」沙箱（可空） |
| 知识库 | 占位，视版本开放 |
| 记忆 | 长/短期记忆策略等（部分能力视版本开放） |

底部：**取消 / 保存草稿 / 发布**。首次发布后通常得到 `v1.0.0` 并进入在线态。

### 4.2 详情页 Tab（配置模式）

| Tab | 内容 |
|-----|------|
| 基本信息 | 名称、描述、提示词、Plan 等 |
| 模型 / Skill / 工具 / 沙箱 / 记忆 | 当前挂载与规格 |
| API 信息 | Open API 路径、字段说明、cURL |
| 秘钥管理 | 创建 / 脱敏查看 / 明文查看（审计）/ 删除 |
| 版本管理 | 草稿编辑、发布、历史快照 |
| 会话历史 | 对外/调试会话记录（视版本） |

顶部常见操作：调试、上线/下线、删除；A2A 另有「手动重新同步」。

### 4.3 版本管理

流程：**创建草稿 → 编辑 → 保存草稿 → 发布**。

发布时选择影响等级并填写变更说明（通常 ≥10 字）：

| 等级 | 典型场景 | 版本示例 |
|------|----------|----------|
| patch | 提示词微调、温度调整 | v1.0.3 → v1.0.4 |
| minor | 加挂/解绑 Skill、限流调整 | v1.0.4 → v1.1.0 |
| major | 模型大换、不兼容变更 | v1.1.0 → v2.0.0 |

已发布历史版本只读；对比/回滚能力视产品版本开放。

### 4.4 秘钥管理

- 创建后**明文只展示一次**，请立即保存  
- 列表脱敏展示；「查看明文」需二次确认并记审计  
- 删除后立即失效；泄漏请立刻删旧建新  

密钥格式一般为 `ak-...`，调用 Open API 时：

```http
Authorization: Bearer ak-xxxxxxxx
```

请求体中的 `agentNum` 必须与密钥归属 Agent 一致，否则返回 403。

## 5. Skill 管理

### 5.1 创建模式

| 模式 | 场景 | 操作 |
|------|------|------|
| DIRECT | 简单 Skill | 元数据 + 在线编写 SKILL.md + 资源文件 |
| UPLOAD | 复杂包 | 上传 ZIP（限大小），根目录须含 `SKILL.md` |

### 5.2 发布检查

发布时自动检查（示例）：

- 大小：SKILL.md / 资源总量上限  
- 格式：YAML 前部元数据合法  
- 可用性：能否正确加载  

通过后状态为「发布」，方可被 Agent 挂载与调试台优先使用。

### 5.3 状态

草稿 → 检查中 → 检查失败 → 发布 → 弃用。

> 「同步公司库」等能力若菜单不可见或提示下线，表示当前环境未开放，以实际页面为准。

### 5.4 详情 Tab

基本信息、资源文件、检测记录、版本管理（对比/回滚视版本）。

## 7. Prompt 中心

- **业务编码 + Prompt Key**：调用与检索的稳定地址  
- **模板内容**：支持 `{{变量名}}`；编辑时展示变量清单  
- 保存后即时可用；Agent 配置中可一键选取填入系统提示词  

运行时变量替换：系统提示词占位符可在 Open API / 调试调用的 `context` 中传入键值完成替换（并可能写入会话默认上下文）。

## 9. 沙箱管理

底层对接 **OpenSandbox**。本期类型主要为**代码沙箱**。

### 9.1 状态机

| 状态 | 含义 | 常见操作 |
|------|------|----------|
| 草稿 | 仅元数据 | 编辑规格、提交、删除 |
| 初始化 | 异步创建容器中 | 规格锁定，可改备注 |
| 在线 | 可被 Agent 挂载 | 下线；可改备注 |
| 下线 | 实例已释放 | 重新上线、删除 |
| 失败 | 供给失败 | 改规格后重新提交、删除 |

### 9.2 新建与提交

填写名称、CPU（0.5 核步进）、内存（MB）、存活时间（分钟）、备注 → 保存为草稿 → **提交**。

提交后接口立即返回「初始化」；平台异步创建容器并做就绪检查（OpenSandbox Running + execd 探活）。成功变为**在线**，失败变为**失败**（可查看失败原因相关提示/事件）。

> 容器镜像由服务端全局配置（如 `SANDBOX_IMAGE`），创建表单不选手动镜像。OpenSandbox 侧可能同时出现 `execd` 组件镜像，属运行时守护进程，非业务表单字段。

### 9.3 对账

平台定时检查在线实例是否仍存活；不存活会校正为下线，避免脏状态。

## 10. 调试台

路径：智能体中心 → **Agent 调试**（`/agent/debug`）。

### 10.1 发起对话

1. 选择**执行 Agent**（必选）  
2. （可选）选择调试 Skill：强制注入该 Skill  
3. 底部输入消息，Enter 发送（Shift+Enter 换行）  
4. `⌘J / Ctrl+J` 可切换 Text / JSON 输入模式  

### 10.2 会话与 Trace

- 顶栏会话胶囊：切换 / 重命名 / 删除 / 新建  
- ThoughtChain：步骤名、入参/出参、状态、耗时；错误步骤高亮  
- 可复制 `trace_id` 供排查  

### 10.3 异常

| 场景 | 表现 |
|------|------|
| 未选 Agent | 发送禁用 + 提示 |
| JSON 校验失败 | 发送禁用 + 错误提示 |
| SSE 中断 | 可重试；已渲染内容保留 |
| 流式进行中 | Loading / 可中止 |

## 11. 评测体系

入口：Skill Hub → **Skill 评测**；或从 Agent / Skill 详情进入相关评测。

### 11.1 Skill 人工评测

选执行 Agent → 输入任务与期望 → 判分方式（LLM Judge / 关键词 / 不判分）→ 执行 → 对比结果；可将好用例保存为种子。

### 11.2 Skill 自动评测

配置执行 Agent、评测 Agent、5 维评分、用例数与数据源 → 生成并执行 → 查看报告（总分、雷达图、用例明细）。

**5 维**：准确性 / 相关性 / 完整性 / 风格一致 / 安全合规。

### 11.3 Agent 评测

| 类型 | 测什么 |
|------|--------|
| 单元（UNIT） | 单点能力 |
| 评估（QUALITY） | 输出质量与连贯性 |
| 轨迹（TRAJECTORY） | 多步工具/行为合理性 |
| 回归（REGRESSION） | 跨版本稳定性 |

### 11.4 种子用例

人工评测「保存为种子」→ 种子库管理 → 自动评测可选用种子数据源。

## 12. 权限与用户管理

具体字段与校验规则以页面表单为准。

## 14. Open API 接口

鉴权：

```http
Authorization: Bearer ak-xxxxxxxx
Content-Type: application/json
```

SSE 建议额外携带：`Accept: text/event-stream`。

完整路径前缀：`/api/v1/open/agents`。详情以 Agent「API 信息」Tab 为准（含当前 Agent 编号替换后的示例）。

### 14.1 接口一览

| 接口 | Method | 路径 | 响应 |
|------|--------|------|------|
| Invoke（Event SSE） | POST | `/api/v1/open/agents/command/invoke` | `text/event-stream` |
| A2UI Invoke | POST | `/api/v1/open/agents/command/a2ui/invoke` | `text/event-stream`（A2UI v0.9.1） |
| A2UI Action | POST | `/api/v1/open/agents/command/a2ui/action` | 同上 |
| 创建会话 | POST | `/api/v1/open/agents/command/createSession` | JSON `Result` |
| 会话列表 | POST | `/api/v1/open/agents/query/sessionList` | JSON `Result` |
| 会话详情 | GET | `/api/v1/open/agents/query/sessionDetail?num=` | JSON `Result` |

非流式统一包装：`{ code, message, data, traceId }`，`code = 0` 表示成功。

### 14.2 Invoke 请求体（摘要）

| 字段 | 必填 | 说明 |
|------|------|------|
| `agentNum` | 是 | 须与秘钥归属一致 |
| `input` | 是 | 用户输入 |
| `inputType` | 否 | 默认 `text` |
| `sessionNum` | 否 | 空则新建会话 |
| `operatorId` | 否 | 空记 `system` |
| `context` | 否 | 扁平键值；替换 `{{key}}` 并合并会话上下文 |

### 14.3 Event SSE（Invoke）

每条 `data:` 为一个 AgentScope **Event** JSON，常见字段：

| 字段 | 说明 |
|------|------|
| `type` | `REASONING` / `TOOL_RESULT` / `AGENT_RESULT` 等 |
| `message` | 消息体（含 `content[]`，按 `type` 判别 text / tool_use 等） |
| `isLast` | 是否该 messageId 最终帧 |
| `messageId` | 同逻辑消息的流式分片共享 |

鉴权失败等可能直接返回 JSON Result，而非 SSE。

### 14.4 A2UI SSE

每条 `data:` 为一个 envelope：`version = "v0.9.1"`，且四选一：

- `createSurface`  
- `updateComponents`  
- `updateDataModel`  
- `deleteSurface`（当前实现默认不下发）  

典型顺序：`createSurface` → `updateComponents` → 多次 `updateDataModel`（如 `/assistantText`）。  
`a2ui/action` 用于客户端交互回传，成功后继续流式下发 UI 更新。

### 14.5 cURL 示例（Invoke）

```bash
curl -N -X POST 'https://<host>/api/v1/open/agents/command/invoke' \
  -H 'Authorization: Bearer ak-xxxxxxxx' \
  -H 'Content-Type: application/json' \
  -H 'Accept: text/event-stream' \
  -d '{
    "agentNum": "AGT...",
    "input": "这个单什么时候发货？",
```

## 15. 常见问题

**Q1：Agent 配置里模型下拉为空？**  
先到模型管理启用至少一个空间模型，或确认系统模型已启用且你有权限看到。

**Q2：Skill 在挂载列表看不到？**  
Skill 须为「已发布」状态。

**Q3：A2A Agent 能编辑吗？**  
不能。以 Nacos 为准，平台只读；可用「手动重新同步」。

**Q4：调试台 SSE 断了怎么办？**  
已渲染内容保留；可重试最后一条用户消息。

**Q5：如何删工作空间？**  
空间内无资产 + 输入完整确认词。

**Q6：`{{变量}}` 谁替换？**  
模板存原文；调用时通过 `context`（或会话默认上下文）替换。

**Q7：秘钥泄漏？**  
立刻删除旧密钥并新建；查看明文有审计。

**Q8：左侧几乎没有菜单？**  
当前角色权限不足。请管理员分配平台角色，或加入空间并绑定空间角色。

**Q9：沙箱一直「初始化」或变「失败」？**  
初始化为异步。失败常见原因：连不上 OpenSandbox、镜像/配额问题、就绪检查（execd）未通过。检查服务端 `SANDBOX_*` 配置与 OpenSandbox 状态后重新提交。

**Q10：Open API 403？**  
检查 `Authorization` 是否有效，以及 body/`agentNum` 是否与密钥归属一致。

## 16. 术语表

| 术语 | 说明 |
|------|------|
| Agent | 智能体；配置或 A2A 接入的任务执行单元 |
| Skill | 技能资产，以 SKILL.md 等描述 |
| MCP | Model Context Protocol，工具接入协议之一 |
| FunctionCall | 函数调用类工具 |
| Prompt | 提示词模板，可含 `{{变量}}` |
| SSE | Server-Sent Events，流式推送 |
| OpenSandbox | 沙箱运行时；含业务镜像与 execd 执行守护 |
| A2UI | Agent 到 UI 的声明式协议（本平台 Open API 支持 v0.9.1） |
| A2A | Agent-to-Agent；本平台指 Nacos 同步模式 |
| Semver | 语义化版本 major.minor.patch |
| ThoughtChain | 调试台步骤链可视化 |
| Bearer Token | `Authorization: Bearer …` 鉴权 |
| Control Plane | 本平台管理面，不替代全部执行面职责 |
