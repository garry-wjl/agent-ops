> **v3.1 变更摘要（2026-06-25, hotfix_20260625_a2a-create-endpoints 同步能力补充）**：A2A "待同步 → 在线" 兜底轮询 + 手动触发实现：
> - **新增 application `A2aSyncApplicationService`**（独立于 `AgentCommandService`）：批处理推进 `status=PENDING_SYNC` 的 A2A Agent 至 PUBLISHED；`syncPendingBatch(int batchSize)` + `syncOne(A2aSyncCandidateVO)` 内部 `@Transactional(propagation = REQUIRES_NEW)` 单条事务；远端不可达 / 关键字段缺失 → 抛 `BusinessException(A2A_REMOTE_UNREACHABLE)`，写 `A2aSyncHistory` 跳过
> - **新增 adapter `A2aSyncController`**（HTTP 入口）：`POST /api/v1/agents/a2aSync/run?batchSize=1..500`，缺省 50，返回 `{processed: N}`；`@Min(1) @Max(500)` 参数校验
> - **新增 adapter `A2aSyncScheduler`**（cron 入口）：`@Scheduled(cron = "0 0/5 * * * ?")` 每 5min 触发；经 Redisson 全局锁 `LockKeyConstant.A2A_SYNC_RECONCILE_LOCK`（租约 280s）保证多副本下只有 1 个实例执行；抢不到锁直接跳过
> - **新增 application `AgentQueryService.listPendingSyncCandidates(int limit)`**：SQL `WHERE creation_mode=A2A AND status=PENDING_SYNC AND deleted=0 AND create_time <= DATE_SUB(NOW(), INTERVAL 1 MINUTE) ORDER BY id LIMIT ?`；1min 冷却窗口避免与 Nacos 首次推送抢跑
> - **新增 infra `LockKeyConstant.A2A_SYNC_RECONCILE_LOCK`**：`"a2a:sync:reconcile:lock"`
> - **入口层分工**：HTTP（Controller）+ cron（Scheduler）→ application 层同一方法 `syncPendingBatch`；与 `AgentCommandService.manualResync` 单条手动不同，本能力是批处理推进
> - **失败隔离**：每条独立事务 + try/catch 包外层循环 → 单条失败仅记日志 + 写历史 + 继续
> - **状态映射**：当前 fetcher 无 healthy 字段，M2 阶段统一按 PUBLISHED 处理（"远端可达即认为在线"）
> - **详见 PRD §6.6.5 + 本方案 §3.2.3.7 / §4.2.1 / §5.2.1 / §11.1.3**

## 1. 目标与范围

### 1.1 目标

- **2 种创建方式**（`CONFIG` / `A2A`）+ **1 种类型**（普通 Agent）的 Agent CRUD；监督者/路由类型 S3 开放；
- 对外暴露统一 invoke 接口（SSE 流式），运行时按 `creation_mode` Strategy 派发到 `ConfigAgentRunner` / `A2aAgentRunner`；
- **A2A 模式**：后台订阅 Nacos `a2a-agents` group，自动发现/同步/下线 A2A Agent；A2A Agent 在平台只读，所有字段（含状态）以 Nacos 为唯一权威源；
- **配置模式版本化机制**（草稿/发布、Semver、备注必填、不可变快照、回滚）；发布时自动生成版本号 + 配置 diff 对比；
- 内置**空白沙盒 Agent** 供 Skill 评测兜底；
- A2A Agent 在所有 mutate 接口（编辑 / 发布 / 下线 / 删除）兜底返回 403。

### 1.2 范围

| 内容 | 范围 |
| --- | --- |
| 业务领域 | `agent`（仅本子需求） |
| 涉及层 | facade / client / domain / infra / application / adapter |
| 不涉及 | session（调试台子需求）、evaluation（评测子需求）、skill 实体（Skill 子需求；本方案仅引用 ID） |

### 1.3 与公共方案的关系

- 共享值对象 `Version` / `ChangeLevel` / `InputType` / `EventType` / `PlatformEvent`：来自 [总体方案 §3.3](./2026-05-11_S2总体-技术方案.md#33-跨领域值对象在-facade-与-domaincommon-共享)
- 公共骨架 `UserContext` / `BizNumGenerator` / `JsonSchemaValidator` / `Result<T>` / `GlobalExceptionHandler` 由本子需求**首发分支携带**（见总体方案 §8）
- Nacos 客户端 SDK：`com.alibaba.nacos:nacos-client`（已在公司基建中存在）

## 3. 领域模型设计

### 3.1 业务层级划分

| 层级 | 业务领域 | 说明 |
| --- | --- | --- |
| L1 资产层 | agent | Agent 元信息 + 版本快照（仅配置模式，含 DRAFT/PUBLISHED/ARCHIVED 三态，v3.0 起草稿合并到此实体） + 2 种 Runner |

### 3.2 agent 领域

#### 3.2.1 领域模型

**聚合与边界**

- 聚合根：`Agent`
- 实体：`AgentVersion`（**v3.0 起承载草稿与历史版本**：通过 `status: AgentVersionStatus` 区分 `DRAFT / PUBLISHED / ARCHIVED`，仅配置模式产生）
- 值对象：`CreationMode`、`AgentType`、`AgentStatus`、`AgentVersionStatus`（v3.0 新增）、`Version`（共享）、`ConfigSnapshot`、`A2aSourceInfo`、`ChangeLevel`（共享）、`AgentRunner`（接口）+ 2 个实现
- 跨聚合引用：仅持有 `skillNum: String`（指向 Skill 聚合）

> **v3.0 关键约束**：领域模型**不再存在 `AgentDraft` 实体**。同 Agent 的草稿、当前在线、历史归档共用同一张 `agent_version`，靠 `status` 字段三态区分；同 agentNum 下任意时刻至多 1 行 `status=DRAFT` 与 1 行 `status=PUBLISHED + current_flag=1`。Agent 聚合根额外冗余 `configSnapshot: ConfigSnapshot` 字段，作为当前在线版本快照的镜像，避免列表 / 详情查询 join `agent_version`。

#### 3.2.2 领域规则

| 聚合/对象 | 规则类型 | 规则描述 | 违反时表达 |
| --- | --- | --- | --- |
| Agent | 不变性 | `agentType ∈ {SUPERVISOR, ROUTER}` 时 `creationMode` 必须为 `CONFIG` | `BizException(2003, "A2A Agent 不支持监督者/路由类型")` |
| Agent | 不变性 | S2 内 `agentType` 固定为 `NORMAL`，`creationMode ∈ {CONFIG, A2A}` | `BizException(2003, "S2 内仅支持普通 Agent + 配置/A2A 模式")` |
| Agent | 不变性 | `creationMode = A2A` 时所有 mutate 操作（createVersion/editDraftVersion/deleteDraftVersion/publish/offline/delete）必须拒绝 | `BizException(2010, "A2A Agent 不可在平台修改，请到 Nacos 操作")` 由 `assertMutableByPlatform()` 兜底 |
| Agent | 不变性 | `creationMode = A2A` 时 `a2aSource` 必填且 `currentVersionNum` 必为 null（不存版本快照） | `BizException(2003)` |
| Agent | 不变性 | `creationMode = CONFIG` 时 `a2aSource` 必为 null | `BizException(2003)` |
| Agent | 不变性 | `status = OFFLINE` 时不可被 invoke / 不出现在调试台/挂载下拉 | invoke 接口返回 `code=2002` |
| Agent | 不变性 | `sandbox=true` 的 Agent 不出现在 Agent 列表（仅供评测内部使用） | 查询时过滤 |
| Agent | 业务规则 | 同 ownerUserId 下 name 不可重复（仅 CONFIG；A2A 不参与该约束，幂等键为 `nacosGroup + nacosService`） | `BizException(1005, "Agent 名称已存在")` |
| AgentVersion | 不变性 | 同 agentNum 下任意时刻 `status=DRAFT` 至多 1 行（v3.0：草稿合并到本实体） | 应用层 `createVersion` 前置 `findByAgentNumAndStatus(DRAFT)` 校验 → `BizException(6002)` |
| AgentVersion | 业务规则 | DRAFT 行编辑者 != 锁定者（`editorUserId` + `lockUntil`） → 显示"被锁定，可接管或等待" | `BizException(6002, "草稿被 X 锁定")` 含 lockUntil |
| AgentVersion | 不变性 | 已发布行（status ∈ {PUBLISHED, ARCHIVED}）的 `configSnapshot / versionNum / changeLevel / publishedBy / publishedAt` 不可修改；DRAFT 行的 `configSnapshot / editorUserId / lockUntil` 可覆盖更新 | DB 层只允许 INSERT 与状态翻转 / DRAFT 的 snapshot UPDATE |
| AgentVersion | 不变性 | 同 agentNum 下任意时刻仅一个 `status=PUBLISHED + current=true` | publish 事务内原子翻转 `switchCurrent(oldId, newId)` |
| ConfigSnapshot | 业务规则 | `agentType ∈ {SUPERVISOR, ROUTER}` 时 childAgentNums 不可为空，且每个子 Agent 必须 `creationMode = CONFIG + agentType = NORMAL` | `BizException(2003)`（A2A Agent 不可作为子 Agent） |
| Version | 不变性 | 首次发布固定 v1.0.0；A2A 不参与版本化 | `Version.initial()` 返回 (1,0,0) |
| AgentRunner | 业务规则 | 2 种 Runner（CONFIG / A2A）必须覆盖全部 CreationMode | Spring 启动时校验，缺失则启动失败 |

#### 3.2.3 领域动作

| 聚合/实体 | 领域动作 | 职责 | 前置条件 | 后置条件/规则 | 领域事件 |
| --- | --- | --- | --- | --- | --- |
| Agent | save(operatorId) | 保存/更新 Agent 元信息 | operatorId 有效 | updateNo 已更新 | — |
| Agent | delete(operatorId) | 逻辑删除 Agent（含所有版本，DRAFT/PUBLISHED/ARCHIVED 一并 deleted=1） | `creationMode = CONFIG` 且 status=OFFLINE 或被强制；operatorId 有权限 | deleted=1 | `AGENT_OFFLINED` |
| Agent | promotePublished(versionNum, snapshot, operatorId) | **v3.0 新增**：发布事务尾部由 publish 调用，把 `agent.currentVersionNum / configSnapshot / status / name / description` 同步为新在线版本（`name / description` 来自 snapshot） | `creationMode = CONFIG`；事务内 | currentVersionNum 已切换；`agent.config_snapshot` JSON 镜像更新；status=PUBLISHED；name/description 同步到主表 | — |
| Agent | offline(operatorId) | 手动下线（仅配置模式；A2A 由 Nacos 同步触发，不走此动作） | `creationMode = CONFIG`；status=PUBLISHED | status=OFFLINE | `AGENT_OFFLINED` |
| Agent | syncFromNacos(card, instance) | A2A 模式：从 Nacos 全字段覆盖更新 | `creationMode = A2A` | a2aSource 全字段覆盖；name/description/status 同步；lastSyncedAt 刷新 | `AGENT_A2A_SYNCED`（status 由 UP→DOWN 时附带触发 `AGENT_OFFLINED`） |
| Agent | assertMutableByPlatform() | 兜底守卫，所有 mutate 动作开头 invoke | — | 若 `creationMode = A2A` → throw `BizException(2010)` | — |
| AgentVersion | save(operatorId) | upsert 当前实体（DRAFT 行允许覆盖 snapshot；已发布行仅允许状态 / current_flag 翻转） | — | createNo/updateNo 已记录 | — |
| AgentVersion | setConfigSnapshot(snap) | **v3.0 新增**：DRAFT 行覆盖配置快照 | status=DRAFT | configSnapshot 已替换 | — |
| AgentVersion | tryLock(editorId, ttlSeconds) | **v3.0 新增**：DRAFT 行尝试锁定编辑权 | status=DRAFT；lockUntil < now 或 editorUserId 一致 | editorUserId=editorId；lockUntil=now+ttl | — |
| AgentVersion | promoteToPublished(versionNum, level, remark, operatorId) | **v3.0 新增**：DRAFT 行升级为 PUBLISHED + 赋 versionNum + current_flag=1；与旧 PUBLISHED 行的 `archive` 在同事务内成对调用 | status=DRAFT；remark ≥ 10 字符；level 有效 | status=PUBLISHED；version 已赋；current=true；editorUserId/lockUntil 清空 | `AGENT_VERSION_PUBLISHED` |
| AgentVersion | archive(operatorId) | **v3.0 新增**：原 PUBLISHED 行降级为 ARCHIVED + current_flag=0 | status=PUBLISHED 且 current=true | status=ARCHIVED；current=false | — |

```mermaid
    Q-->>AppSvc: List<A2aSyncCandidateVO>

    loop 逐条(单条 REQUIRES_NEW 事务)
        AppSvc->>Fetcher: fetch(name)
        alt 远端可达
            Fetcher-->>AppSvc: A2aSourceInfo
            AppSvc->>Factory: createByNum(num) -> Agent
            alt Agent 仍为 A2A + PENDING_SYNC
                AppSvc->>Agent: applyNacosSync(source, PUBLISHED,<br/>SyncEventType.POLLING_RECONCILE, "nacos-sync")
                Agent->>Agent: status=PUBLISHED<br/>a2aSource 全字段覆盖
                AppSvc->>Repo: save(A2aSyncHistory{POLLING_RECONCILE, source})
            else 数据竞态(已非 A2A 或 status 变更)
                AppSvc-->>AppSvc: skip (info 日志)
            end
        else BusinessException(A2A_REMOTE_UNREACHABLE)
            AppSvc->>Repo: save(A2aSyncHistory{POLLING_RECONCILE, errorMessage})
            AppSvc-->>AppSvc: skip (warn 日志)
        end
    end

    AppSvc-->>Cron: processed = N
    AppSvc-->>Ctrl: processed = N
    Ctrl-->>Ctrl: ok(Map.of("processed", N))
    Cron->>Lock: unlock()
```

## 11. 其他

### 11.1 关键技术点

- **Strategy 派发**：`Map<CreationMode, AgentRunner>` 由 Spring 自动注入，应用层 `runners.get(agent.creationMode).invoke(ctx)`。
- **A2A 写入保护双层兜底**：① 前端不渲染编辑/发布/下线按钮；② Service 层 `Agent.assertMutableByPlatform()` 在所有 mutate 动作开头调用，A2A 直接抛 `BizException(2010)`；**v2.4 起 `delete` 不再被该守卫拦截**，因为 UI 取消订阅是合法路径。
- **Nacos 长订阅 + 兜底轮询**：**v2.4 改**：订阅范围 = DB 中 `creation_mode=A2A` 的 Agent 集合（运行时动态）。`A2aNacosSubscriber` 启动时 `agentRepository.listByCreationMode(A2A)` 全量装载，对每个 name 调 `aiService.subscribeAgentCard(name, listener)`；新建 / 取消订阅时通过 `subscribe(name)` / `unsubscribe(name)` 即时变更；`@Scheduled(fixedDelay=poll-interval-ms)` 对当前订阅集合调 `getAgentCard` 对账。
- **A2A PENDING_SYNC 兜底轮询 + 手动触发（v3.1 hotfix_20260625）**：用户接入完成后 status=PENDING_SYNC 等待首次 Nacos AgentCard 推送；当长订阅延迟 / 漏推时由 `A2aSyncScheduler`（cron 5min）+ `A2aSyncController`（HTTP `POST /api/v1/agents/a2aSync/run`）双入口打到 `A2aSyncApplicationService.syncPendingBatch`，主动调 `NacosAgentCardFetcher.fetch(name)` 拉远端推进至 PUBLISHED。**入口层分工**：HTTP / cron 都打到 application 层同一方法（区别于 `AgentCommandService.manualResync` 单条手动重试，本能力是批处理推进）。**1min 冷却窗口**：`AgentQueryService.listPendingSyncCandidates` SQL 加 `create_time <= NOW()-1min`，避免与 Nacos 首次推送抢跑。**多副本并发**：Redisson 全局锁 `LockKeyConstant.A2A_SYNC_RECONCILE_LOCK`（租约 280s）保证同一时刻只有一个实例执行；抢不到锁的副本直接跳过本轮（参考 `SandboxReconcileScheduler` 模式）。**单条事务隔离**：`syncOne` 标注 `@Transactional(propagation = REQUIRES_NEW)`，外层 try/catch 循环 — 单条失败仅记日志 + 写 `A2aSyncHistory` 跳过，不影响后续条。**状态映射策略**：当前 fetcher 无 `healthy` 字段时统一按 PUBLISHED 处理（"远端可达即认为在线"）；后续接 Nacos 实例健康度时再扩展。**触发错误码**：`NacosAgentCardFetcher` 远端不可达 → `BusinessException(A2A_REMOTE_UNREACHABLE)` (2011)，`A2aSyncApplicationService` 内 catch 后写历史跳过，不抛回调用方。
- **A2A 幂等键**：`agent.nacos_service_key = "{nacosGroup}@@{nacosService}"`，UNIQUE KEY 兜底；首次发现走 INSERT，后续走 UPDATE。
- **A2A 全字段覆盖**：`Agent.syncFromNacos()` 用 Nacos 来源覆盖 `name / description / a2aSource.* / status`；本地任何字段修改都会被刷掉（事实上本地无修改入口，此为一致性兜底）。
- **A2A 状态映射**：Nacos `instance.healthy = true` → `PUBLISHED`；`healthy = false` 或 `DEREGISTER` 事件 → `OFFLINE`；状态变化时附带触发 `AGENT_OFFLINED` 事件用于通知调试台/评测下拉刷新。
- **A2aProtocolAdapter**：把 A2A 协议事件（task.update / task.complete / message 等）映射到平台 5 类标准事件（message.delta / step.start / step.end / final / error），映射表硬编码在 Adapter 内。
- **SseEmitter**：`new SseEmitter(0L)` 不超时；emitter 在 final 事件后 `complete()`。
- **草稿冲突锁**：`AgentVersion` DRAFT 行的 `editorUserId / lockUntil` + Redisson 分布式锁双保险（DB 锁兜底，Redis 锁热路径）。**v3.0 起锁字段下沉到 `agent_version`**，与配置快照同表，避免 v2.x 双表（`agent_draft` + 锁列）一致性维护。
- **空白沙盒 Agent**：DDL 初始化时种入；不出现在列表（`sandbox=1` 过滤）；Skill 评测台执行 Agent 下拉时通过特殊接口拿到。

```java
// ── infra/agent/builder/OpenAiChatModelFactory.java ─────────────────────────
@Component
public class OpenAiChatModelFactory {
    /**
     * 用 ConfigSnapshot 中的模型秘钥/URL/型号实例化 OpenAiChatModel。
     * <p>
     * v2.8 起强制从 DB 读取，不再回落 Spring 默认 Bean。任一字段缺失抛 MODEL_NOT_CONFIGURED。
     *
     * @param snap CONFIG Agent 当前在线版本的快照
     * @return 可执行的 OpenAiChatModel 实例（每次新建，由 AgentInstanceCache 缓存复用）
     */
    public OpenAiChatModel resolve(ConfigSnapshot snap) {
        if (StrUtil.isBlank(snap.getModelApiKey())
                || StrUtil.isBlank(snap.getModelBaseUrl())
                || StrUtil.isBlank(snap.getModel())) {
            throw new BusinessException(BizCode.MODEL_NOT_CONFIGURED.getCode(),
                    "Agent 未配置模型秘钥 / URL / 型号；请在 Agent 详情 → 模型配置 中补全");
        }
        OpenAiApi api = OpenAiApi.builder()
                .baseUrl(snap.getModelBaseUrl())
                .apiKey(snap.getModelApiKey())
                .build();
        return OpenAiChatModel.builder()
                .openAiApi(api)
                .defaultOptions(OpenAiChatOptions.builder()
                        .model(snap.getModel())
                        .temperature(snap.getTemperature())
                        .build())
                .build();
    }
}

    private final AgentVersionReadGateway versionReadGateway;

    /**
     * 按 agentType 派发到 spring-ai-alibaba 对应 Agent。
     * @param agent 当前 Agent 元信息
     * @param snap  当前在线版本的 ConfigSnapshot
     * @return BaseAgent；按 NORMAL/SUPERVISOR/ROUTER 分别为 ReactAgent/SupervisorAgent/LlmRoutingAgent
     */
    public BaseAgent build(Agent agent, ConfigSnapshot snap) {
        if (StrUtil.isBlank(snap.getModel())) {
            throw new BusinessException(BizCode.MODEL_NOT_CONFIGURED.getCode(),
                    "Agent 未配置模型 num=" + agent.getNum());
        }
        OpenAiChatModel model = chatModelFactory.resolve(snap);
        switch (agent.getAgentType()) {
            case NORMAL: return buildReact(agent, snap, model);
            case SUPERVISOR: return buildSupervisor(agent, snap, model);
            case ROUTER: return buildRouter(agent, snap, model);
            default: throw new BusinessException(BizCode.INVALID_PARAM.getCode(),
                    "未知 agentType=" + agent.getAgentType());
        }
    }

    private ReactAgent buildReact(Agent agent, ConfigSnapshot snap, OpenAiChatModel model) {
        return ReactAgent.builder()
                .name(agent.getName())
                .description(agent.getDescription())
                .model(model)
                .instruction(snap.getSystemPrompt())
                .outputKey("messages")
                // .tools(...) // S3 接入 Skill / MCP 时填
                .build();
    }

    private SupervisorAgent buildSupervisor(Agent agent, ConfigSnapshot snap, OpenAiChatModel model) {
        // mainAgent：用同一份 systemPrompt 作为决策入口，由 spring-ai-alibaba 强约束（缺则 IllegalArgument）
        ReactAgent mainAgent = ReactAgent.builder()
                .name(agent.getName() + "_main")
                .model(model)
                .description("Supervisor decision entry for " + agent.getName())
                .systemPrompt(snap.getSystemPrompt())
                .build();
        List<BaseAgent> subs = buildSubAgents(snap.getChildAgentNums());
        return SupervisorAgent.builder()
                .name(agent.getName())
                .description(agent.getDescription())
                .model(model)
                .mainAgent(mainAgent)
                .subAgents(subs)
                .build();
    }

    private LlmRoutingAgent buildRouter(Agent agent, ConfigSnapshot snap, OpenAiChatModel model) {
        List<BaseAgent> subs = buildSubAgents(snap.getChildAgentNums());
        return LlmRoutingAgent.builder()
                .name(agent.getName())
                .description(agent.getDescription())
                .model(model)
                .systemPrompt(snap.getSystemPrompt())
                .instruction(snap.getUserPrompt())
                .subAgents(subs)
                .build();
    }

    /** 递归构建子 Agent；强校验子 Agent 必须 CONFIG + NORMAL + 在线 */
    private List<BaseAgent> buildSubAgents(List<String> childNums) {
        if (CollUtil.isEmpty(childNums)) return List.of();
        List<BaseAgent> result = new ArrayList<>(childNums.size());
        for (String num : childNums) {
            Agent sub = agentRepository.findByNum(num);
            if (sub == null || sub.getCreationMode() != CreationMode.CONFIG
                    || sub.getAgentType() != AgentType.NORMAL
                    || sub.getStatus() != AgentStatus.PUBLISHED) {
                throw new BusinessException(BizCode.SUBAGENT_NOT_AVAILABLE.getCode(),
                        "子 Agent 不可用 num=" + num);
            }
            ConfigSnapshot subSnap = versionReadGateway.findCurrent(num).getConfigSnapshot();
            result.add(build(sub, subSnap)); // 递归（注：子 Agent 也会进缓存，由调用方 wrap）
        }
        return result;
    }
}

// ── application/agent/cache/AgentInstanceCache.java ────────────────────────
@Component
@RequiredArgsConstructor
@Slf4j
public class AgentInstanceCache {
    /** key = "{agentNum}::{versionNum}"；value = spring-ai-alibaba BaseAgent 实例 */
    private final Map<String, BaseAgent> cache = new ConcurrentHashMap<>();

    /**
     * 命中即复用，未命中由 supplier 构造并入缓存。
     * @param agentNum   Agent 业务编号
     * @param versionNum 当前在线版本号（保证同 Agent 不同版本独立缓存）
     * @param supplier   未命中时构造 BaseAgent 的 lambda（一般是 ConfigAgentBuilder.build(...)）
     * @return 可复用的 BaseAgent
     */
    public BaseAgent getOrBuild(String agentNum, String versionNum, Supplier<BaseAgent> supplier) {
        String key = agentNum + "::" + versionNum;
        return cache.computeIfAbsent(key, k -> {
            log.info("[AgentInstanceCache] miss → build key={}", key);
            return supplier.get();
        });
    }

    /** 单 Agent 全版本失效（发布新版本 / 下线 / 删除时调用） */
    public void invalidateByAgentNum(String agentNum) {
        String prefix = agentNum + "::";
        int removed = 0;
        Iterator<String> it = cache.keySet().iterator();
        while (it.hasNext()) {
            if (it.next().startsWith(prefix)) {
                it.remove();
                removed++;
            }
        }
        if (removed > 0) {
            log.info("[AgentInstanceCache] invalidated agentNum={} removed={}", agentNum, removed);
        }
    }
}

// ── application/agent/cache/AgentInstanceCacheInvalidator.java ─────────────
@Component
@RequiredArgsConstructor
public class AgentInstanceCacheInvalidator {
    private final AgentInstanceCache cache;

    /** 监听领域事件，发布 / 下线 / 删除时清缓存 */
    @EventListener({ AgentVersionPublishedEvent.class,
                     AgentOfflinedEvent.class,
                     AgentDeletedEvent.class })
    public void onAgentChanged(Object event) {
        String agentNum = extractAgentNum(event); // 三个事件都有 agentNum 字段
        cache.invalidateByAgentNum(agentNum);
    }
}
```

#### 关键设计取舍

- **CacheKey 用 `{agentNum}::{versionNum}` 而非 `{agentNum}` 单独**：发布新版本时旧版本缓存项也保留（仍可被未来"按版本号 invoke"复用），但通过 invalidateByAgentNum 主动清除，避免 stale；这种取舍简化失效逻辑（不必区分版本对比），代价是切版本期间多消耗内存
- **不预加载**：缓存懒构建，避免启动 N×LLM client 实例化
- **不限容量**：S2 单进程 Agent 数量预期 < 100，简单 ConcurrentHashMap 够用；S3 可演进为 Caffeine + maxSize + TTL
- **递归构建子 Agent 也走缓存**：`ConfigAgentBuilder.buildSubAgents` 内部应通过 cache.getOrBuild 而非直接 build，避免子 Agent 重复实例化（实施时由 application 层 wrapper 处理）
- **A2A 不入此缓存**：A2A 走 `A2aAgentRunnerImpl` 的 `A2aRemoteAgent`，spring-ai-alibaba 内部带 InMemoryMemory，单例化会跨请求串对话历史
- **缓存命中后中途 Agent 状态变化**：依靠领域事件 invalidate；监听 `AGENT_VERSION_PUBLISHED` / `AGENT_OFFLINED` / `AGENT_DELETED` 三个事件即可覆盖所有失效场景

### 11.3 测试要点

- **单测**（≥ 70% 覆盖率）：`Version.next()` 三种场景；2 种 Runner 选择逻辑（CONFIG / A2A）；ConfigSnapshot 校验；publish 事务原子性；`Agent.assertMutableByPlatform()` 对 A2A 抛 2010；`Agent.syncFromNacos()` 全字段覆盖
- **集成测**（Testcontainers MySQL + Redis + Nacos mock-server）：草稿冲突检测端到端；publish 后 current 翻转；rollback 生成新草稿；Nacos 事件 → A2A Agent upsert；Nacos 实例下线 → 状态同步 OFFLINE；A2A mutate 接口返回 403；兜底全量轮询补漏

### 11.4 风险与应对

| 风险 | 应对 |
| --- | --- |
| Nacos 长订阅丢失事件 | 5min 兜底全量对账；监控告警长订阅断开 |
| A2A Agent 在 Nacos 元数据格式不规范 | `NacosAgentCardFetcher` 校验 `agent_card` 字段或 `.well-known/agent.json` 必须存在；不规范实例直接忽略 |
| 本地有人通过 SQL 直接改 A2A Agent | 下次 Nacos 同步时全字段覆盖刷掉；应用层绝无 mutate 入口 |
| A2A 远端 endpoint 不可达 | invoke 时返回 `error` 事件，不影响其他 Agent；`AGENT_A2A_SYNCED` 事件保留状态 |
| 接入式凭证泄露（A2A） | A2A 走 Nacos 内网调用，无凭证下发；如远端要求鉴权由 Nacos 元数据 token 字段透传，不前端回显 |
| 草稿锁僵死 | lockUntil 默认 30min；超时自动释放（DB 兜底） + Redis lock TTL 双保险 |
| invoke SSE 占满 Tomcat 线程 | `server.tomcat.threads.max=400`；S3 评估迁 WebFlux |

### 11.5 监控与日志

- 业务日志：`createAgent` / `publishVersion` / `invoke 入口` / `A2A nacos sync` / `A2A manualResync` 各 INFO 一行
