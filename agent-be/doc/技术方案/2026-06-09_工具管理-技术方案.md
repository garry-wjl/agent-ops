## 0. 设计前共识（12 问纪要）

设计前与负责人确认，结论作为本方案约束（避免实现期返工）：

| # | 议题 | 结论 |
| --- | --- | --- |
| 1 | 部署架构处理方式 | **不变，无需设计**：工具管理是 rd-agent-be 内新模块，无新增应用/前端部署实例，复用现有部署架构。 |
| 2 | 运行时调用边界 | **仅资产 CRUD + 挂载列表**：本方案只交付工具资产的建/编/发布/弃用/列表/详情/复用数 + 给 Agent 挂载用的「已发布工具列表」查询。MCP 代理转发、`OpenApiToMcpAdapter`、变量注入等运行时调用作为后续 agentrunner 方案单列。 |
| 3 | 聚合粒度 | **单一 `Tool` 聚合 + JSON 值对象**：S2 不做版本化；`endpoints[]` / `proxyHeaders[]` / `mcpConfig` / `openApiSpec` 全部作为值对象内嵌，落库为 `tool` 表的 JSON/text 列。无 `ToolVersion` 实体、无端点子表。 |

| 5 | Agent Step4 改造 | **纳入本方案范围**：把 Agent 管理 CONFIG 模式 Step4 的 mock 切换为真实「已发布工具列表」数据源；`AgentCommandService` 保存时校验挂载的 mcpNum 为 `PUBLISHED`。Agent 领域 `ConfigSnapshot.mcpNums` 已存在，不改领域模型。 |
| 6 | MCP 代理字段深度 | **仅存配置 + 格式校验**：落库 `proxyEnabled` + `proxyHeaders`（JSON），变量占位符 `{\w+}` 格式校验后端兜底；`BuiltinVariableRegistry` 与运行时变量解析不在本方案。 |
| 7 | OpenAPI 解析 | **发布时解析端点元数据**：发布动作内把 `openApiSpec` 解析为端点摘要（端点数 / path / method / summary）落 `endpointMeta`（JSON），供列表展示端点数与详情预览；原文仍存 `openApiSpec`。复用同一解析器服务 MCP API 打包两种来源。 |
| 8 | 引用一致性 | **引用检查 + 动态跟随**：弃用/删除 FC 工具前，经 QueryService 校验是否被任何 `packageMode=EXISTING_API` 的 MCP 工具引用，被引用则拒绝弃用并提示；MCP API 打包动态跟随来源 FC 工具最新已发布配置。 |
| 9 | name 唯一性 | **工作空间内强唯一**（不区分 type）：DB `uq(workspace_num, name, deleted)`；创建/发布前端失焦调后端 check。 |
| 10 | 三态机模式 | **复用 Skill 三态机**：`DRAFT / PUBLISHED / DEPRECATED`；领域动作 `save / publish / unpublish(重新发布走 publish) / delete`；编辑已发布 → 状态回 `DRAFT`（复用同一记录，无版本表）；草稿物理删，已发布/已废弃软删。 |
| 11 | 创建发布语义 | **创建仅草稿，publish 独立**：`createTool` 只落 `DRAFT`；前端「直接发布」= 调 `createTool` 后再调 `publish`，两接口分离（区别于 Skill 的「创建即首发」）。 |
| 12 | 挂载/复用数接口归属 | **均为查询类**：「已发布工具列表」「复用数下钻 Agent 列表」由 `ToolQueryController`（GET）提供。 |

## 1. 目标与范围

### 1.1 目标

- 在 rd-agent-be 内新增 **工具（tool）领域**，承载 MCP 与 FunctionCall 两类工具的目录化管理；
- 支持 **4 种创建方式**：MCP 远程连接、MCP API 打包、FunctionCall OpenAPI Spec 导入、FunctionCall 手动录入；
- 实现 **草稿 / 已发布 / 已废弃** 三态机与编辑回滚草稿语义；
- 对外提供「已发布工具列表」查询，承接 **Agent 管理 Step4 由 mock 切真实数据源**；
- 提供工具 **复用数**（被多少已发布 Agent 挂载）与反向下钻 Agent 列表。

### 1.2 范围

**做**：工具 CRUD、4 种创建方式落库与发布校验、三态机、MCP 代理字段存储 + 透传 Header 格式校验、OpenAPI 发布时端点元数据解析、MCP API 打包引用 FC 工具的一致性校验、工作空间内 name 唯一、reuseCount 实时统计、Agent Step4 数据源切换 + 挂载校验。

**不做**（运行时，单列后续方案）：MCP 代理实际转发、`OpenApiToMcpAdapter` 运行时封装、`BuiltinVariableRegistry` 变量注入、调用配额/费用、工具版本化、工具评测、跨工作空间共享。

**关键调用关系与命令/查询划分：**

- **命令类**（`ToolCommandController` → `ToolCommandService`）：`createTool`（仅草稿）、`updateTool`（编辑→回 DRAFT）、`publish`、`unpublish`（含重新发布）、`deleteDraft`。CommandService 经 `ToolFactory` 构建/加载领域对象，调用 `Tool` 领域动作落库；写操作加 Redis 分布式锁。
- **查询类**（`ToolQueryController` → `ToolQueryService`）：`pageList`、`detail`、`listMountable`（给 Agent Step4 的已发布工具列表）、`reuseCount` + `listMountedAgents`（复用数下钻）、`existsByName`（唯一性预检）、`existsReferencedByMcp`（FC 弃用前引用检查）。QueryService 经 infra `ToolMapper` / `AgentMapper` 只读查询返回 DTO。
- **依赖方向**：adapter → application → (domain + infra)；domain 仅依赖 facade。application **禁止注入 Repository / Gateway**，跨领域读取（如 reuseCount 扫 Agent）统一走 QueryService 的 Mapper 只读查询。
- **同步/异步边界**：本方案全部同步；reuseCount 实时 count，无异步事件依赖。领域事件（`TOOL_*`）经现有 `DomainEventPublisher` 发布到审计基础设施，与 Skill/Agent 同链路。

### 4.2 工具（tool）

#### 4.2.1 领域模型

**领域结构表：**

| 对象 | 类型 | 关键属性 | 与其它对象关系 |
| --- | --- | --- | --- |
| `Tool` | 聚合根（extends DomainEntity） | num / name / description / type / creationMode / tags / status / workspaceNum / ownerUserId + 各创建方式专有字段 | 持有 ToolRepository / ToolGateway / DomainEventPublisher（transient 装配依赖） |

| `CreationMode` | 值对象（enum） | REMOTE / API_PACKAGE / OPENAPI_SPEC / MANUAL | Tool.creationMode；建好不可改 |
| `ToolStatus` | 值对象（enum） | DRAFT / PUBLISHED / DEPRECATED | Tool.status；系统派生 |
| `McpConfigType` | 值对象（enum） | LOCAL / REMOTE | 仅 type=MCP,creationMode=REMOTE 使用 |
| `PackageMode` | 值对象（enum） | EXISTING_API / OPENAPI_PASTE | 仅 type=MCP,creationMode=API_PACKAGE 使用 |
| `ProxyHeader` | 值对象 | name / value / description | Tool.proxyHeaders 列表项；value 可含 `{变量名}` |
| `ApiEndpoint` | 值对象 | method / path / description / queryParams / pathParams / headers | Tool.endpoints 列表项（MANUAL） |

| `ApiHeader` | 值对象 | name / defaultValue / description | ApiEndpoint.headers 项 |
| `EndpointMeta` | 值对象 | endpointCount / summaries | 发布时由 OpenAPI 解析填充（OPENAPI_SPEC / API_PACKAGE-OPENAPI_PASTE） |

**基本属性（强制）**：`id`、`num`、`create_no`、`update_no` 均具备（`id`/createTime/updateTime/deleted 继承自 `DomainEntity`，`createNo`/`updateNo` 即 create_no/update_no）。聚合根持有三类领域协作依赖：`ToolRepository`、`ToolGateway`、`DomainEventPublisher`（均 transient，由 `ToolFactory` 装配）。

**软删除标记约束（强制）**：`Tool` 聚合内不出现 `is_deleted/deleted/isDeleted` 业务字段；`deleted` 仅作为 `DomainEntity` 持久化审计标识由基类管理，infra Entity / DB 表承载，聚合领域动作不读写它做业务判断。

**必备动作（强制）**：`save(operatorId)`、`delete(operatorId)` 均实现；所有领域动作均带 `operatorId`。

#### 4.2.2 领域动作

| 聚合/实体 | 领域动作 | 职责 | 前置条件 | 后置条件/规则 | 领域事件 |
| --- | --- | --- | --- | --- | --- |
| Tool | `save(operatorId)` | 保存/更新工具元信息（草稿态 upsert） | 无状态约束；name/type/creationMode 非空 | status 为空兜底 DRAFT；num 为空则 `generateToolNum`；按 type+creationMode 做形态字段校验 | `TOOL_SAVED` |
| Tool | `publish(operatorId)` | 草稿 → 已发布；全字段必填 + 形态完整性校验；OpenAPI 形态解析端点元数据 | status==DRAFT | 走全量 `domainValidate`；OPENAPI 形态经 Gateway 解析 `endpointMeta`；status=PUBLISHED | `TOOL_PUBLISHED` |
| Tool | `unpublish(operatorId)` | 已发布 → 已废弃（弃用）/ 已废弃 → 已发布（重新发布，见说明） | status==PUBLISHED（弃用）或 status==DEPRECATED（重新发布） | 弃用置 DEPRECATED；重新发布置 PUBLISHED | `TOOL_DEPRECATED` / `TOOL_PUBLISHED` |
| Tool | `delete(operatorId)` | 物理/逻辑删除工具 | status==DRAFT（仅草稿可硬删） | 草稿物理删（deleteByNum）；非草稿禁删抛业务异常 | `TOOL_DELETE_DRAFT` |

> **重新发布说明**：PRD 状态机「已废弃 → 已发布（重新发布）」与「草稿 → 已发布（发布）」是两条不同跃迁。实现上 `Tool` 提供 `publish`（DRAFT→PUBLISHED，含发布校验与端点解析）与 `republish`（DEPRECATED→PUBLISHED，仅切状态不重解析）两个方法，避免在一个方法里混判前置状态。下文时序图分别给出。

```mermaid
    Tool->>Tool: 2.规则校验 status==DRAFT 否则禁删
    Tool->>Repo: 5.deleteByNum(num) 物理删
    Tool->>Pub: 6.send(TOOL_DELETE_DRAFT)
```

#### 4.2.3 领域规则

| 聚合/对象 | 规则类型 | 规则描述 | 违反时表达 |
| --- | --- | --- | --- |
| Tool | 不变性 | name/description/type/creationMode 必填；description ≤500 字符 | BusinessException 7001 参数非法 |
| Tool | 不变性 | tags ≤20 个，单 tag ≤32 字符 | BusinessException 7001 |
| Tool | 形态约束 | type=MCP+REMOTE：mcpConfigType + mcpConfig 必填且合法 JSON（≤64KB） | BusinessException 7002 MCP 配置非法 |
| Tool | 形态约束 | type=MCP+API_PACKAGE：packageMode 必填；EXISTING_API→sourceFcToolNum 必填，OPENAPI_PASTE→openApiSpec 必填 | BusinessException 7003 打包配置非法 |
| Tool | 形态约束 | type=FC+OPENAPI_SPEC：openApiSpec 必填且合法（≤1MB） | BusinessException 7004 OpenAPI 非法 |
| Tool | 形态约束 | type=FC+MANUAL：baseUrl 合法 URL；endpoints ≥1 且 ≤50；path 占位符与 pathParams 一一对应 | BusinessException 7005 端点配置非法 |
| Tool | 代理约束 | proxyEnabled=false 时 proxyHeaders 必须为空；header 名工具内不重复（大小写不敏感）；value 变量占位仅 `{\w+}` | BusinessException 7006 代理配置非法 |
| Tool | 状态约束 | publish 仅 DRAFT；unpublish 仅 PUBLISHED；republish 仅 DEPRECATED；delete 仅 DRAFT | BusinessException 7007 状态非法 |
| Tool | 引用约束 | 被任何 MCP API 打包工具引用的 FC 工具不可弃用/删除（应用层经 QueryService 前置校验） | BusinessException 7008 工具被引用 |

> 形态校验仅在 `publish`（全量）执行；`save` 草稿态仅校验 name/type/creationMode（PRD §7.7.5）。形态分支校验封装为 `Tool` 私有方法 `validateByShape()`，由 `domainValidate` 在发布路径调用。

#### 4.2.4 领域工厂

`ToolFactory` 接口由 domain 定义、infra 实现，仅 2 个方法：

| Factory | 方法名 | 入参 | 返回值 | 职责 | 依赖 |
| --- | --- | --- | --- | --- | --- |
| ToolFactory | `create(...)` | name, description, type, creationMode, tags, + 各形态业务字段（mcpConfigType/mcpConfig/proxyEnabled/proxyHeaders/packageMode/sourceFcToolNum/openApiSpec/baseUrl/endpoints） | Tool（未落库，已装配依赖） | 用创建工具时用户填写的业务字段构建新 Tool；status 不在此赋值（由 save 兜底 DRAFT） | 装配 Repository/Gateway/EventPublisher |
| ToolFactory | `createByNum(num)` | num | Tool（已装配依赖，不存在返回 null） | 经 Repository.findByNum 加载既有 Tool 并装配依赖 | ToolRepository |

> **create 参数约束**：`create(...)` 入参仅含用户可填字段；不含 `operatorId`、createNo/updateNo、status、num、审计字段、endpointMeta（系统派生）。`workspaceNum` 由 FactoryImpl 内部从 `WorkspaceContextHolder` 注入（与 Skill/Sandbox 一致），不作为业务可见入参。`ownerUserId` 由应用层在 save 前 set（或由 create 接收——与现有 SkillFactory 一致，作为负责人字段允许入参）。
> 不设计 `createById` / `rebuild` 等其它方法。`createByNum` 时序内部经 Repository 获取数据并构建对象。

**`createByNum` 时序：**

```mermaid
sequenceDiagram
    participant App as ToolCommandService
    participant F as ToolFactoryImpl
    participant Repo as ToolRepository

    App->>F: createByNum(num)
    F->>Repo: findByNum(num)
    Repo-->>F: Tool / null
    alt Tool 存在
        F->>F: wire(Repository/Gateway/EventPublisher)
        F-->>App: Tool（可直接执行领域动作）
    else 不存在
        F-->>App: null
    end
```

#### 4.2.5 领域网关

`ToolGateway` 接口定义在 domain，infra 实现 `ToolGatewayImpl`：

| Gateway | 方法名 | 入参 | 返回值 | 职责 | 外部依赖 | 失败策略 |

## 8. 数据库设计

| --- | --- | --- | --- |
| `id` | BIGINT AUTO_INCREMENT | ✓ | 主键，自增 |
| `num` | VARCHAR(64) | ✓ | 业务编号 MCP+/FC+ 前缀；唯一索引 |
| `workspace_num` | VARCHAR(64) | ✓ | 归属工作空间；默认 WS-DEFAULT |
| `name` | VARCHAR(128) | ✓ | 工具名称；(workspace_num,name,deleted) 唯一 |
| `description` | VARCHAR(500) | ✓ | 描述 |
| `type` | VARCHAR(32) | ✓ | MCP / FUNCTION_CALL；建好不可改 |
| `creation_mode` | VARCHAR(32) | ✓ | REMOTE/API_PACKAGE/OPENAPI_SPEC/MANUAL |
| `tags` | JSON | — | 标签数组 |
| `status` | VARCHAR(16) | ✓ | DRAFT/PUBLISHED/DEPRECATED；默认 DRAFT |
| `mcp_config_type` | VARCHAR(16) | — | LOCAL/REMOTE（MCP-REMOTE 用） |
| `mcp_config` | TEXT | — | MCP 配置 JSON 原文（≤64KB） |
| `proxy_enabled` | TINYINT(1) | ✓ | 是否启用代理；默认 0 |
| `proxy_headers` | JSON | — | 透传请求头数组 [{name,value,description}] |

## 11. 实现顺序与依赖

按六层依赖推进（facade 无变更，跳过）：

1. **client**（impl-client-module）：先定 Param/DTO/Vo 与 BizCode 契约；
2. **domain**（impl-domain-module）：Tool 聚合 + 值对象 + Repository/Factory/Gateway 接口 + 领域事件；
3. **infra**（impl-infra-module）：Entity/Mapper/RepositoryImpl/FactoryImpl/GatewayImpl + V18 迁移 + 事件常量；与 §8 数据库、§4 domain 接口相互校验；
4. **application**（impl-application-module）：ToolCommand/QueryService → 再改造 Agent Step4（依赖 ToolQueryService 就绪）；
5. **adapter**（impl-adapter-module）：Controller + Assembler。

里程碑对齐：M1 优先 client/domain/infra/application 的 MCP 远程 + FC 手动 + 三态机 + 列表；M2 补 MCP API 打包 + FC OpenAPI 解析 + 代理字段 + Agent Step4 切换 + 弃用引用检查；M3 补详情/复用数下钻/废弃工具 tooltip。
