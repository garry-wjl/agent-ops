# Nacos 3 节点集群部署方案（PostgreSQL）

> AgentOps · Control Plane / Data Plane 共用注册中心
>
> 版本：Nacos 3.2.x（develop 分支当前 SNAPSHOT；首次正式发布版本以 release tag 为准）
> 数据库：**公司云 PostgreSQL（DBaaS）**，14+
> 部署形态：3 节点集群（奇数，满足 JRaft quorum）
> 部署平台：**公司内部 K8s 集群**（StatefulSet）
>
> 待决字段统一标记为 `<TBD: 含义>`，上线前由 SRE / 平台架构填实。

---

## 1. 目标与非目标

**目标**
- 给 rd-agent-be / rd-points-sphere / 业务侧服务提供高可用的注册中心 + 配置中心 + AI Registry（A2A / MCP / Prompt）
- 任意 1 节点宕机 ≤ 30s 自动切换、不丢数据、外部 SDK 无感
- 数据落公司云 PostgreSQL（DBaaS 提供主备 / 备份 / 监控 / 容灾，本方案不重复建设）

**非目标**
- 跨地域多 Region 部署（S2 不做，留 S3+）
- 复用现有 Nacos 实例做迁移（本方案是新建集群，不涉及数据迁移）
- 自建 PG（已有云 PG 服务，无需自建）
- 物理机 / VM 部署（已有 K8s，本方案不再覆盖 VM 路径）

```
│ nacos-0      │       │ nacos-1      │       │ nacos-2      │
│ StatefulSet  │       │ StatefulSet  │       │ StatefulSet  │
│ JRaft Leader │◄─────►│  Follower    │◄─────►│  Follower    │
│  9848/9849   │       │  9848/9849   │       │  9848/9849   │
└──────┬───────┘       └──────┬───────┘       └──────┬───────┘

                      │                      │
                      ▼                      ▼
             ┌──────────────────────────────────────┐
             │  PostgreSQL Primary + Standby (DBA) │
             │  nacos schema, owner = nacos_rw     │
             │  <TBD: 集群域名 / 端口>              │
             └──────────────────────────────────────┘
```

**端口约定**

| 端口 | 协议 | 用途 | 暴露范围 |
|------|------|------|---------|
| 8848 | gRPC + HTTP | SDK 客户端 | 内网（业务服务）|
| 8080 | HTTP | Web 控制台 + Admin API | 内网（限运维 IP）|
| 9848 | gRPC | 节点间通信 | 集群内 Pod 互通 |
| 9849 | gRPC | 节点间通信 | 同上 |

## 3. 资源清单（部署前必须就绪）

### 3.1 PostgreSQL（公司云 DBaaS）

通过工单向 DBA 申请，**不要自建实例**。申请单需明确：

| 项 | 要求 |
|---|---|
| 服务形态 | 公司云 PostgreSQL DBaaS（主备高可用，DBaaS 内置 failover） |
| 版本 | PostgreSQL 14+（13 也可，但 14 起官方推荐） |
| 规格起步 | 4C 16G + 200GB SSD（业务量上来按 IOPS 扩） |
| 实例数 | 1 个（DBaaS 内部主备对外暴露 1 个 endpoint，业务无感） |
| 数据库 | `nacos`，UTF8，owner = `nacos_rw` |
| 业务账号 | `nacos_rw`：schema 内 DML+DDL；`nacos_ro`（可选）：只读，给 BI / 排错 |
| 网络 | 加入 K8s 集群 nacos namespace 的访问白名单（Pod 出口 NAT IP 段）|
| 端口暴露 | 5432（DBaaS 内网 endpoint，不走公网）|
| 备份 | DBaaS 默认全备 + WAL 归档；RPO ≤ 1min |
| 监控 / 告警 | DBaaS 标准接入（连接数 / 慢查询 / 复制延迟），告警通道 `<TBD>` |
| 慢查询阈值 | 200ms 起步，上线后按实际调 |

申请单回执后，记录以下值进入第 3.4 节 K8s Secret：

```
DB_HOST       = <TBD: DBaaS 内网 endpoint 域名>
DB_PORT       = 5432
DB_NAME       = nacos
DB_USER       = nacos_rw
DB_PASSWORD   = <TBD: 工单分发或 Vault 取>
```

### 3.2 Schema 初始化（一次性）

源 SQL（自编译仓库内）：

[`代码仓库/nacos/plugin-default-impl/nacos-default-datasource-plugin/nacos-datasource-plugin-postgresql/src/main/resources/META-INF/pg-schema.sql`](../代码仓库/nacos/plugin-default-impl/nacos-default-datasource-plugin/nacos-datasource-plugin-postgresql/src/main/resources/META-INF/pg-schema.sql)（556 行）

云 PG 通常**不允许**业务直接 `psql` 连入做 DDL，二选一：

**方式 A：DBaaS 控制台 SQL 编辑器**（多数云 PG 支持）
1. 用 superuser 登入 DBaaS 控制台
2. 选 `nacos` 数据库 → 打开 SQL 编辑器
3. 粘贴 `pg-schema.sql` 全文执行（一次性，556 行 1~2 秒完成）
4. 再粘 `pg-grant-nacos-readwrite.sql` 给 `nacos_rw` 授权

**方式 B：DBA 工单提交 SQL 脚本**
- 把上面两个 SQL 文件附进工单，注明 "owner=nacos_rw, db=nacos"
- DBA 执行后回执，业务侧只验证表数量

**验证（任一 K8s 节点 exec 到任意有 psql 客户端的 pod）：**
```bash
PGPASSWORD=$DB_PASSWORD psql -h $DB_HOST -U nacos_rw -d nacos \
  -c "\dt" | wc -l   # 应 ≥ Nacos 标准表数量（config_info / users / roles / instances / agent_card / ai_resource 等 30+）
```

### 3.3 K8s 资源

| 项 | 起步规格 |
|---|---|
| Namespace | `nacos`（独立，配 NetworkPolicy） |
| 节点反亲和 | 3 Pod 必须落到 3 个不同 Node（podAntiAffinity required）|
| Pod 资源 | requests 2C 4Gi / limits 4C 8Gi（小流量起步，按 metrics 调） |
| PVC | 每 Pod 20Gi（仅日志 + JRaft 元数据，业务数据在 PG） |
| Storage Class | `<TBD: 公司 SSD storageclass>` |
| Service | ClusterIP（gRPC + HTTP）+ Headless（StatefulSet 必须） |
| Ingress / LB | 8080 走运维 LB（限白名单），8848 内部 ClusterIP 即可 |

### 3.4 鉴权

| 项 | 选择 |
|---|---|
| 内置 nacos/nacos 账号 | **必须改密 / 关闭**（生产事故重灾区） |
| 鉴权插件 | `<TBD: 公司 SSO 走 OIDC plugin / 还是 RAM plugin>` |
| `nacos.core.auth.server.identity.key/value` | 节点间通信秘钥，**必须**自定义 + 注入 K8s Secret |
| Token 加密 key | `nacos.core.auth.plugin.nacos.token.secret.key` 至少 32 位 base64 |

### 3.5 网络 / NetworkPolicy

```
ingress 允许:
  - 业务 Pod CIDR → :8848  (SDK)
  - 运维 LB → :8080         (控制台)
  - 集群内 nacos Pod → :9848/9849 (节点互通)
egress 允许:
  - → PG 主备 :5432
  - → 集团 OIDC IDP（如启用 SSO）
  - → DNS
```

## 4. K8s 部署（首选）

### 4.1 镜像

```
<TBD: 公司 Harbor 镜像地址>/nacos-server:<TBD: 自编译 tag>
```

构建来源：
```bash

```

### 4.2 ConfigMap：`application.properties` 关键项

```properties
# === 数据源（公司云 PG）===
spring.sql.init.platform=postgresql
db.num=1
# host/port/db 由 Secret 注入到环境变量，再用 Spring 占位符引用
db.url.0=jdbc:postgresql://${DB_HOST}:${DB_PORT}/${DB_NAME}?currentSchema=public&reWriteBatchedInserts=true&sslmode=${DB_SSL_MODE:disable}
db.user.0=${DB_USER}
db.password.0=${DB_PASSWORD}
db.pool.config.connection-timeout=30000
db.pool.config.maximum-pool-size=20

# === 集群 ===
# cluster.conf 不放这里，由 init container 按 StatefulSet 序号生成

# === 鉴权（必改）===
nacos.core.auth.enabled=true
nacos.core.auth.system.type=nacos
nacos.core.auth.plugin.nacos.token.secret.key=${TOKEN_SECRET}
nacos.core.auth.server.identity.key=${SERVER_IDENTITY_KEY}
nacos.core.auth.server.identity.value=${SERVER_IDENTITY_VALUE}

# === gRPC ===
nacos.remote.server.grpc.sdk.max-inbound-message-size=10485760

# === AI Registry（业务必需）===
nacos.ai.registry.enabled=true             # A2A/MCP/Prompt 子模块
```

### 4.3 Secret

云 PG 的 host / port / db / user / password 全部走 Secret，**不入 ConfigMap、不入 Git**。建议用公司 Vault / SealedSecret 而非裸 Secret 入仓库。

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: nacos-secrets
  namespace: nacos
type: Opaque
stringData:
  # 云 PG 连接信息（DBA 工单回执填）
  DB_HOST: "<TBD: 云 PG 内网 endpoint 域名>"
  DB_PORT: "5432"
  DB_NAME: "nacos"
  DB_USER: "nacos_rw"
  DB_PASSWORD: "<TBD>"
  DB_SSL_MODE: "<TBD: 云 PG 是否强制 TLS，require / verify-full / disable>"

  # Nacos 集群内秘钥（必须自定义，不能用源码默认值）
  TOKEN_SECRET: "<TBD: openssl rand -base64 64>"
  SERVER_IDENTITY_KEY: "<TBD>"
  SERVER_IDENTITY_VALUE: "<TBD: openssl rand -base64 32>"
```

### 4.4 StatefulSet 关键片段

```yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: nacos
  namespace: nacos
spec:
  serviceName: nacos-headless
  replicas: 3
  podManagementPolicy: Parallel
  selector:
    matchLabels: { app: nacos }
  template:
    metadata:
      labels: { app: nacos }
    spec:
      affinity:
        podAntiAffinity:
          requiredDuringSchedulingIgnoredDuringExecution:
            - labelSelector:
                matchLabels: { app: nacos }
              topologyKey: kubernetes.io/hostname
      initContainers:
        - name: gen-cluster-conf
          image: busybox
          command:
            - sh
            - -c
            - |
              for i in 0 1 2; do
                echo "nacos-${i}.nacos-headless.nacos.svc.cluster.local:8848"
              done > /nacos/conf/cluster.conf
          volumeMounts:
            - { name: conf, mountPath: /nacos/conf }
      containers:
        - name: nacos
          image: <TBD: Harbor>/nacos-server:<tag>
          env:
            - { name: MODE, value: "cluster" }
            - { name: NACOS_SERVER_PORT, value: "8848" }
            - { name: PREFER_HOST_MODE, value: "hostname" }
            # 云 PG 连接信息：全部从 Secret 注入
            - { name: DB_HOST,     valueFrom: { secretKeyRef: { name: nacos-secrets, key: DB_HOST     } } }
            - { name: DB_PORT,     valueFrom: { secretKeyRef: { name: nacos-secrets, key: DB_PORT     } } }
            - { name: DB_NAME,     valueFrom: { secretKeyRef: { name: nacos-secrets, key: DB_NAME     } } }
            - { name: DB_USER,     valueFrom: { secretKeyRef: { name: nacos-secrets, key: DB_USER     } } }
            - { name: DB_PASSWORD, valueFrom: { secretKeyRef: { name: nacos-secrets, key: DB_PASSWORD } } }
            - { name: DB_SSL_MODE, valueFrom: { secretKeyRef: { name: nacos-secrets, key: DB_SSL_MODE } } }
            # Nacos 集群秘钥
            - { name: TOKEN_SECRET, valueFrom: { secretKeyRef: { name: nacos-secrets, key: TOKEN_SECRET } } }
            - { name: SERVER_IDENTITY_KEY, valueFrom: { secretKeyRef: { name: nacos-secrets, key: SERVER_IDENTITY_KEY } } }
            - { name: SERVER_IDENTITY_VALUE, valueFrom: { secretKeyRef: { name: nacos-secrets, key: SERVER_IDENTITY_VALUE } } }
          ports:
            - { containerPort: 8848, name: client }
            - { containerPort: 8080, name: console }
            - { containerPort: 9848, name: grpc-1 }
            - { containerPort: 9849, name: grpc-2 }
          readinessProbe:
            httpGet: { path: /nacos/v3/health/readiness, port: 8080 }
            initialDelaySeconds: 30
          livenessProbe:
            httpGet: { path: /nacos/v3/health/liveness, port: 8080 }
            initialDelaySeconds: 60
          resources:
            requests: { cpu: "2", memory: "4Gi" }
            limits:   { cpu: "4", memory: "8Gi" }
          volumeMounts:
            - { name: conf, mountPath: /nacos/conf }
            - { name: data, mountPath: /nacos/data }
            - { name: logs, mountPath: /nacos/logs }
      volumes:
        - { name: conf, emptyDir: {} }
  volumeClaimTemplates:
    - metadata: { name: data }
      spec:
        accessModes: ["ReadWriteOnce"]
        storageClassName: <TBD: SSD storageClass>
        resources: { requests: { storage: 20Gi } }
    - metadata: { name: logs }
      spec:
        accessModes: ["ReadWriteOnce"]
        storageClassName: <TBD>
        resources: { requests: { storage: 20Gi } }
```

### 4.6 NetworkPolicy（强制写）

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: { name: nacos-policy, namespace: nacos }
spec:
  podSelector: { matchLabels: { app: nacos } }
  policyTypes: [Ingress, Egress]
  ingress:
    - from:
        - namespaceSelector: { matchLabels: { tier: business } }   # 业务 ns
      ports:
        - { protocol: TCP, port: 8848 }
    - from:
        - ipBlock: { cidr: <TBD: 运维堡垒机 CIDR> }
      ports:
        - { protocol: TCP, port: 8080 }
    - from:
        - podSelector: { matchLabels: { app: nacos } }            # 集群内
      ports:
        - { protocol: TCP, port: 9848 }
        - { protocol: TCP, port: 9849 }
  egress:
    - to:
        - ipBlock: { cidr: <TBD: 云 PG 内网 endpoint 解析后的 IP/CIDR；DBaaS 域名走 DNS 时也要在 NetworkPolicy 之外配 dnsPolicy/CoreDNS 透传> }
      ports:
        - { protocol: TCP, port: 5432 }
    - to:
        - namespaceSelector: { matchLabels: { name: kube-system } }
      ports:
        - { protocol: UDP, port: 53 }                              # DNS
```

> **NetworkPolicy 与云 DBaaS 的小坑**：云 PG 通常给的是域名，需先解析成 IP 才能写 ipBlock；建议 SRE 提前确认云 PG endpoint 的 IP 段是否稳定（部分云会跨段漂移，那种情况下要么放宽 CIDR，要么用 ServiceEntry / external Service 绕过）。

## 5. 集群健康验证

```bash

curl -u nacos:<密码> http://nacos.<内网域名>:8080/nacos/v3/admin/core/cluster/nodes

# 2. PG 连通性（任一节点）

# 4. JRaft 选举状态

# 5. AI Registry 可用
curl -X POST http://nacos:8080/nacos/v3/admin/ai/agent/list -d '{}'
```

## 7. 灰度上线 + 回滚

### 上线步骤
1. **DBaaS 工单**：申请云 PG 实例 + 加 K8s nacos namespace 出口白名单 → 拿到 endpoint / 账号
2. **schema 初始化**：DBaaS 控制台 SQL 编辑器跑 `pg-schema.sql` + `pg-grant-nacos-readwrite.sql`（第 3.2 节）
3. **镜像就位**：本地 `mvn -Prelease-nacos clean install` → `docker build` → 推公司 Harbor，记录 tag
4. **K8s apply**（按依赖顺序）：Namespace → NetworkPolicy → Secret（含 DB conn 信息）→ ConfigMap → Service → StatefulSet（podManagementPolicy=Parallel 加快首次启动）
5. 等 3/3 Pod ready + JRaft leader 选出（看启动日志的 `RaftPeerInfoEvent` / `LeaderTransfer`）
6. 跑健康验证清单（第 5 节）
7. **业务侧切流**：先 1 个低优业务接 `nacos.<内网域名>:8848`，跑 24h 观察 leader 切换次数 / PG 连接池 / gRPC 延迟 P99；OK 再批量切

### 回滚
- 若 Pod 启动失败 / 连不上 PG → `kubectl rollout undo statefulset/nacos -n nacos`；联系 DBA 确认网络白名单生效
- 若数据异常 → DBaaS 走 point-in-time recovery（DBaaS 自带，回到事故前 N 分钟）
- 若集群脑裂 → 找单一 Pod 关停 + JRaft 自愈，必要时清 `data/protocol/` 重新选举
