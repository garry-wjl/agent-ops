## 1. 背景

### 1.1 问题现象

调试台流式输出在本轮(streaming)阶段能完整展示 `thinking → tool_use(含参数) → tool_result(含返回) → text` 的真实交错。但**刷新页面**或**切换会话回到历史消息**后,助手回复只剩一段裸文本,工具调用、思考过程、工具返回全部丢失。

### 1.2 根因(已定位)

后端 `AgentInvokeService.invokeStream`([rd-agent-be-application/.../AgentInvokeService.java:92-95](../代码仓库/rd-agent-be/rd-agent-be-application/src/main/java/ink/garry/rd/agent/ws/application/debugconsole/AgentInvokeService.java#L92-L95))在收到 `event.isLast() && AGENT_RESULT` 时,仅持久化:

```java
sessionCommandService.appendAssistantMessage(
    finalSessionNum,
    event.getMessage().getTextContent(),  // ← 只拿 text 块,丢弃 thinking / tool_use / tool_result
    null,                                  // ← stepChain 传 null
    finalSessionNum,
    operatorId
);
```

`Msg.getTextContent()` 是 AgentScope `Msg` 的便捷方法,只把 `TextBlock` 拼成字符串,**完全丢弃**:
- ThinkingBlock(深度思考内容)
- ToolUseBlock(工具调用 + 参数)
- ToolResultBlock(工具返回)
- 多块之间的真实交错顺序

前端 `Console.AssistantMessage`([rd-agent-fe/src/pages/Console/index.tsx:928](../代码仓库/rd-agent-fe/src/pages/Console/index.tsx#L928))判断 `msg.segments?.length > 0` 才走 `AssistantSegmentList`。历史消息 `segments` 永远为 `undefined`,只能降级到纯文本渲染。

### 1.3 业务影响

- **调试体验断层**:刷新即丢上下文,无法回看上一轮工具调用细节
- **复盘困难**:trace 联调时只能看到最终文本,无法对照中间步骤
- **评测数据缺失**:未来评测要复用调试台轨迹做 case 时,数据不可用

## 2. 目标与非目标

### 2.1 目标

1. **历史消息渲染与本轮流式 100% 一致** — 用户在任何时机进入会话,都能看到完整的 thinking / tool_use / tool_result 交错视图
2. **协议同构** — BE 持久化的"段"结构与 FE `AssistantSegment` 类型完全对齐,FE 渲染层零分叉
3. **向后兼容** — 旧消息(无新字段)继续走原降级渲染路径,不丢
4. **可追溯** — 同时持久化 AgentScope 原生 `Msg.content` block 列表,供未来 trace 导出、评测数据生成、协议升级时回填

### 2.2 非目标

- ❌ **不做事件流回放**(选项 A) — 不存每一帧 SSE event,只存"最终段"。如未来需要"逐帧录像"再做 invocation_event 表
- ❌ **不修改 SSE 流式协议** — 流式期间前后端协议不变,只在持久化和历史读取路径增量
- ❌ **不做数据迁移** — 旧消息不回填,新消息走新路径
- ❌ **不优化 LLM 调用性能或 token 计数** — 与本方案正交

## 3. 现状梳理

### 3.1 BE 当前持久化路径

```
DebugInvokeController.invoke
  → AgentInvokeService.invokeStream
    → agent.stream(msg)                          // AgentScope SDK
      → Flux<Event> { REASONING / TOOL_RESULT / AGENT_RESULT / SUMMARY / HINT }
    → flatMap: event.isLast && AGENT_RESULT
      → sessionCommandService.appendAssistantMessage(
            sessionNum,
            event.getMessage().getTextContent(),  // 仅 text
            null,                                  // stepChain
            traceId,
            operatorId)
```

`Session.appendAssistantMessage` 把 content + stepChain 存到 `message` 表(具体表结构见 `domain/session/`)。

**说明**:仓库里还有一个 `DebugInvokeStreamService.saveResult`,它会把 `state.content.toString()`(chunk 累积)+ `StepChain` 存进去 — 但这个方法当前**没有任何调用方**(已被 AgentInvokeService 替代,残留代码,本方案落地时一并清理)。

### 3.2 BE 域模型现状

`domain/session/valueobject/`:
- `StepNode` { stepId, skillName, input, output, status, latencyMs, error }
- `StepChain` { steps: List<StepNode> }
- `PlatformEvent` { type: EventType, data: Map }

**缺失**:对应 FE `AssistantSegment` 的"段"概念 — 包含 thinking / text / tool_use 三类。当前 `StepNode` 只能表达"工具步骤",不能表达 thinking / text 段。

### 3.3 FE 当前协议

`rd-agent-fe/src/types/session.ts`:

```ts
export type AssistantSegment =
  | { kind: 'thinking'; text: string }
  | { kind: 'text'; text: string }
  | {
      kind: 'tool_use';
      toolCallId: string;
      toolName: string;
      argsBuffer: string;
      input?: Record<string, unknown>;
      status: 'pending' | 'success' | 'error';
      output?: unknown;
      latencyMs?: number;
      startedAt?: string;
      error?: string;
    };
```

`MessageVO` 当前只有 `content + stepChain`,**无** `segments` 字段。

### 3.4 AgentScope SDK 关键观察(io.agentscope:agentscope-core:1.0.12)

- `agent.stream(msg)` 默认 `StreamOptions.defaults()`:`incremental=true`、`includeReasoningResult=true`、`includeActingChunk=true`
- 每段 reasoning 输出:N 个 `ReasoningChunkEvent`(isLast=false,增量) + 1 个 `PostReasoningEvent`(isLast=true,**累积完整 Msg**)
- 每次工具执行:1 个 `PostActingEvent`(isLast=true,完整 `ToolResultBlock`)
- 最终:1 个 `AGENT_RESULT`(isLast=true,完整对话消息) + 可选 `SUMMARY`(达到 maxIters)

**关键利好**:PostReasoning 和 PostActing 的 isLast=true 帧已经给出累积视图,**BE 累积器只需订阅这两类帧**,不需要复刻 FE 的 chunk delta 累积和 tool_use fragment 拼接逻辑。

## 4. 总体设计

### 4.1 方案选型(已决)

**选项 B(段持久化)主 + 选项 C(blocks 兜底)辅**:

- **主字段** `segments_json`:与 FE `AssistantSegment` 同构的有序段列表 — FE 直接消费,零适配
- **兜底字段** `content_blocks_json`:AgentScope `Msg.content` 原始 block 列表 — 不用于渲染,留作 trace 导出、协议升级、评测数据生成的"原始事实"

### 4.2 整体数据流

```
                          ┌─────────────────────────────────┐
agent.stream(msg)         │  AgentInvokeService              │
  Flux<Event>             │                                  │
  ───────────────────────►│  SegmentAccumulator              │
  REASONING isLast=true   │    + content_blocks 按时序 push  │
  TOOL_RESULT isLast=true │    + segments 按 appendBlock /   │
  AGENT_RESULT isLast=true│      applyToolResult 累积        │
                          │                                  │
                          │  onComplete →                    │
                          │    appendAssistantMessage(       │
                          │      content,                    │
                          │      segments,                   │
                          │      contentBlocks,              │
                          │      stepChain  // 从 segments   │
                          │                 //   裁出 tool   │
                          │                 //   节点保留)   │
                          └────────────┬────────────────────-┘
                                       ▼
                          ┌─────────────────────────────────┐
                          │  message 表                      │
                          │   + segments_json TEXT           │
                          │   + content_blocks_json TEXT     │
                          │   + 原 content / step_chain_json │
                          └─────────────────────────────────-┘
                                       ▼
                          GET /sessions/{num}/messages
                                       ▼
                          MessageVO {
                            content,           // 旧字段
                            stepChain,         // 旧字段(兼容)
                            segments,          // ★ 新字段
                            // contentBlocks 不返给 FE,内部留存
                          }
                                       ▼
                          FE Console.AssistantMessage:
                            msg.segments?.length > 0
                              ? <AssistantSegmentList />   ← 与本轮一致
                              : <降级>                      ← 旧消息
```

## 5. 数据模型变更

### 5.1 数据库 schema

`rd_agent.message` 表(具体表名以现有 schema 为准,见 `infra/.../mapper/`):

```sql
ALTER TABLE rd_agent.message
  ADD COLUMN segments_json       TEXT NULL COMMENT 'AssistantSegment[] JSON,助手消息按到达顺序的段列表;USER/TOOL 消息为 NULL',
  ADD COLUMN content_blocks_json TEXT NULL COMMENT 'AgentScope Msg.content 原始 ContentBlock[] JSON,供 trace 导出 / 评测数据复用';
```

**容量预估**:
- 单条 segment 平均 ~200B(thinking/text 居多),典型消息 5~15 段 → segments_json ~3KB
- content_blocks_json 同数量级,略大(保留完整结构)
- 设上限 256KB(与现有 `CONTENT_LIMIT` 对齐),超限走截断逻辑(§9)

**索引**:无新增。这两个字段是"读时反序列化",不参与查询。

### 5.2 Domain / Facade 类型(Java)

#### 5.2.1 `domain/session/valueobject/AssistantSegment`

与 FE `AssistantSegment` 严格同构。用密封类 + Jackson `@JsonTypeInfo` 处理 kind 多态:

```java
package ink.garry.rd.agent.ws.domain.session.valueobject;

import com.fasterxml.jackson.annotation.JsonSubTypes;
import com.fasterxml.jackson.annotation.JsonTypeInfo;
import lombok.Data;
import java.util.Map;

/**
 * 助手消息按到达顺序的段。与 FE AssistantSegment 同构,Jackson 多态序列化按 kind 字段路由。
 * <p>BE 累积器(SegmentAccumulator)按 AgentScope PostReasoning / PostActing 的 isLast 帧累积。
 */
@JsonTypeInfo(use = JsonTypeInfo.Id.NAME, property = "kind", visible = true)
@JsonSubTypes({
        @JsonSubTypes.Type(value = AssistantSegment.Thinking.class, name = "thinking"),
        @JsonSubTypes.Type(value = AssistantSegment.Text.class,     name = "text"),
        @JsonSubTypes.Type(value = AssistantSegment.ToolUse.class,  name = "tool_use"),
})
public sealed interface AssistantSegment
        permits AssistantSegment.Thinking, AssistantSegment.Text, AssistantSegment.ToolUse {

    String kind();

    @Data
    final class Thinking implements AssistantSegment {
        private String text;
        @Override public String kind() { return "thinking"; }
    }

    @Data
    final class Text implements AssistantSegment {
        private String text;
        @Override public String kind() { return "text"; }
    }

    @Data
    final class ToolUse implements AssistantSegment {
        private String toolCallId;
        private String toolName;
        private String argsBuffer;
        private Map<String, Object> input;
        /** pending / success / error */
        private String status;
        private Object output;
        private Integer latencyMs;
        private String startedAt;
        private String error;
        @Override public String kind() { return "tool_use"; }
    }
}
```

**放置层**:`domain/session/valueobject/` — domain 层值对象。如需在 facade 层 DTO 中出现,在 facade 加同名 DTO + 转换(facade 不能依赖 domain)。

#### 5.2.2 不引入新表,继续用 `message` 表

考虑过新建 `message_segment` 子表(每段一行),否决理由:
- 段数量少(平均 < 20),JSON 列读取 + 反序列化成本低于多次 JOIN
- 不参与查询,关系化收益为零
- 与 `stepChain` 当前 JSON 列存法一致,降低运维异质性

`infra/session/entity/MessageEntity`:

## 6. BE 改造 — 应用层累积器

### 6.1 新增组件 `SegmentAccumulator`

放在 `application/debugconsole/SegmentAccumulator.java`(或 `application/agent/` 视依赖位置)。**线程安全**:每次 invoke 创建新实例,不复用。

```java
package ink.garry.rd.agent.ws.application.debugconsole;

import ink.garry.rd.agent.ws.domain.session.valueobject.AssistantSegment;
import io.agentscope.core.agent.Event;
import io.agentscope.core.agent.EventType;
import io.agentscope.core.message.ContentBlock;
import io.agentscope.core.message.Msg;
import io.agentscope.core.message.TextBlock;
import io.agentscope.core.message.ThinkingBlock;
import io.agentscope.core.message.ToolResultBlock;
import io.agentscope.core.message.ToolUseBlock;
import lombok.Getter;

import java.time.Instant;
import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

/**
 * 调试台流式期间累积 AssistantSegment + AgentScope ContentBlock 原始列表。
 *
 * <p>订阅策略:只看 PostReasoning / PostActing 的 isLast=true 帧 —— AgentScope 已在这两帧给出
 * 累积视图,无需复刻 chunk delta 累积或 tool_use fragment 拼接逻辑。
 *
 * <p>线程模型:每次 invoke 创建一个实例,在 Reactor flatMap 内调用 accept()。AgentScope
 * Flux 默认串行下发同 sink 的事件,无需额外加锁。
 */
public class SegmentAccumulator {

    @Getter
    private final List<AssistantSegment> segments = new ArrayList<>();

    @Getter
    private final List<ContentBlock> contentBlocks = new ArrayList<>();

    /** toolCallId -> 开始时间戳(ms),用于 tool_result 到达时算 latency */
    private final Map<String, Long> toolStartedAt = new HashMap<>();

    public void accept(Event event) {
        if (!event.isLast()) {
            // chunk 帧只用于记录 tool_use 出现时间(便于后续算 latency)
            if (event.getType() == EventType.REASONING && event.getMessage() != null) {
                for (ContentBlock b : event.getMessage().getContent()) {
                    if (b instanceof ToolUseBlock t) {
                        toolStartedAt.putIfAbsent(t.getId(), System.currentTimeMillis());
                    }
                }
            }
            return;
        }

        if (event.getType() == EventType.REASONING) {
            handleReasoning(event.getMessage());
        } else if (event.getType() == EventType.TOOL_RESULT) {
            handleToolResult(event.getMessage());
        }
        // AGENT_RESULT / SUMMARY / HINT:不再追加,避免与 REASONING 重复
        // (AGENT_RESULT 等价于 REASONING 最后一帧的 text 总和;前端协议同此约定)
    }

    private void handleReasoning(Msg msg) {
        if (msg == null) return;
        List<ContentBlock> blocks = msg.getContent();
        for (ContentBlock b : blocks) {
            contentBlocks.add(b);

            if (b instanceof ThinkingBlock tb) {
                appendThinking(tb.getThinking());
            } else if (b instanceof TextBlock tx) {
                appendText(tx.getText());
            } else if (b instanceof ToolUseBlock tu) {
                appendToolUse(tu);
            }
            // 其他类型(image/audio/video):本期忽略
        }
    }

    private void handleToolResult(Msg msg) {
        if (msg == null) return;
        for (ContentBlock b : msg.getContent()) {
            contentBlocks.add(b);
            if (b instanceof ToolResultBlock tr) {
                applyToolResult(tr);
            }
        }
    }

    /** 与 FE appendBlock 等价:同类相邻段合并文本,否则新建段 */
    private void appendThinking(String delta) {
        if (delta == null || delta.isEmpty()) return;
        if (!segments.isEmpty()
                && segments.get(segments.size() - 1) instanceof AssistantSegment.Thinking last) {
            last.setText(last.getText() + delta);
            return;
        }
        AssistantSegment.Thinking seg = new AssistantSegment.Thinking();
        seg.setText(delta);
        segments.add(seg);
    }

    private void appendText(String delta) {
        if (delta == null || delta.isEmpty()) return;
        if (!segments.isEmpty()
                && segments.get(segments.size() - 1) instanceof AssistantSegment.Text last) {
            last.setText(last.getText() + delta);
            return;
        }
        AssistantSegment.Text seg = new AssistantSegment.Text();
        seg.setText(delta);
        segments.add(seg);
    }

    /**
     * PostReasoning 的 isLast=true 帧 tool_use 已是完整(name 真实,input 完整对象)
     * 不需要 fragment 拼接;按 id 去重,同 id 已有段则不重复添加(BE 防御性)。
     */
    private void appendToolUse(ToolUseBlock block) {
        for (AssistantSegment s : segments) {
            if (s instanceof AssistantSegment.ToolUse t && block.getId().equals(t.getToolCallId())) {
                // 已存在,补齐可能漏掉的字段
                if (t.getInput() == null && block.getInput() != null) t.setInput(block.getInput());
                if (t.getToolName() == null || t.getToolName().isEmpty()) t.setToolName(block.getName());
                return;
            }
        }
        AssistantSegment.ToolUse seg = new AssistantSegment.ToolUse();
        seg.setToolCallId(block.getId());
        seg.setToolName(block.getName());
        seg.setInput(block.getInput());
        seg.setArgsBuffer(block.getInput() == null ? "" : JsonUtils.toJson(block.getInput()));
        seg.setStatus("pending");
        seg.setStartedAt(Instant.now().toString());
        segments.add(seg);
    }

    /** 反向找最近一个匹配 id 的 tool_use,回填 output / status / latency */
    private void applyToolResult(ToolResultBlock block) {
        for (int i = segments.size() - 1; i >= 0; i--) {
            if (segments.get(i) instanceof AssistantSegment.ToolUse t
                    && block.getId().equals(t.getToolCallId())) {
                t.setOutput(flattenToolOutput(block.getOutput()));
                t.setStatus("success");
                Long startedAt = toolStartedAt.remove(block.getId());
                if (startedAt != null) {
                    t.setLatencyMs(Math.toIntExact(System.currentTimeMillis() - startedAt));
                }
                return;
            }
        }
        // 未匹配:孤立 tool_result,记录到 segments 末尾以便 trace 排查
        // (按需,可只 log warn 而不入段)
    }

    /** 与 FE flattenToolOutput 同构:纯 text 块拼字符串,否则原样 */
    private Object flattenToolOutput(List<ContentBlock> output) {
        if (output == null || output.isEmpty()) return null;
        StringBuilder sb = new StringBuilder();
        boolean allText = true;
        for (ContentBlock b : output) {
            if (b instanceof TextBlock t) {
                if (sb.length() > 0) sb.append('\n');
                sb.append(t.getText());
            } else {
                allText = false;
                break;
            }
        }
        return allText ? sb.toString() : output;
    }
}
```

> `JsonUtils.toJson` 是项目内既有 JSON 工具(若不存在,用 Hutool `JSONUtil.toJsonStr` 或注入 ObjectMapper)。

### 6.2 改造 `AgentInvokeService.invokeStream`

```java
@Transactional
public Flux<Event> invokeStream(String agentNum, String input, String sessionNum, String operatorId) {
    AgentBase agent = agentRunnerFactory.build(agentNum);

    if (StrUtil.isBlank(sessionNum)) {
        SessionDTO dto = sessionCommandService.createSession(
                agentNum, "", StrUtil.sub(input, 0, 10), operatorId);
        sessionNum = dto.getNum();
    }
    sessionCommandService.appendUserMessage(sessionNum, input, InputType.TEXT, sessionNum, operatorId);
    agent.loadIfExists(redisSession, sessionNum);

    Msg msg = Msg.builder().textContent(input).build();
    String finalSessionNum = sessionNum;

    // ★ 新增:本次 invoke 的段累积器
    SegmentAccumulator acc = new SegmentAccumulator();

    return agent.stream(msg)
            .doOnNext(acc::accept)   // ★ 每帧都喂累积器(内部按 isLast 过滤)
            .flatMap(event -> {
                if (event.isLast() && EventType.AGENT_RESULT.equals(event.getType())) {
                    return Mono.fromRunnable(() ->
                            sessionCommandService.appendAssistantMessage(
                                    finalSessionNum,
                                    event.getMessage().getTextContent(),  // 旧字段保留(兼容)
                                    acc.getSegments(),                     // ★ 新字段
                                    acc.getContentBlocks(),                // ★ 新字段
                                    finalSessionNum,
                                    operatorId))
                        .subscribeOn(Schedulers.boundedElastic())
                        .then(Mono.just(event));
                }
                return Flux.just(event);
            })
            .doOnComplete(() -> agent.saveTo(redisSession, finalSessionNum));
}
```

### 6.3 `SessionCommandService.appendAssistantMessage` 签名扩展

当前签名(推断):

```java
void appendAssistantMessage(String sessionNum, String content, StepChain stepChain,
                            String traceId, String operatorId);
```

扩展为:

```java
void appendAssistantMessage(String sessionNum,
                            String content,
                            List<AssistantSegment> segments,
                            List<ContentBlock> contentBlocks,
                            String traceId,
                            String operatorId);
```

**stepChain 取舍**:从 `segments` 中提取所有 `ToolUse` 段拼成 `StepChain` 落库(保留旧字段,FE 老降级路径可用),或者保留参数兼容老逻辑、新增的两个字段单独走。建议**派生 stepChain**,避免双源数据不一致:

```java
StepChain stepChain = StepChain.builder()
        .steps(segments.stream()
                .filter(s -> s instanceof AssistantSegment.ToolUse)
                .map(s -> toStepNode((AssistantSegment.ToolUse) s))
                .toList())
        .build();
```

- `selectByXxx` 默认带出(不要单独 `selectFields`,避免漏掉)

### 7.2 MessageRepositoryImpl

```java
public Message save(Message domain) {
    MessageEntity entity = mapper.toEntity(domain);
    entity.setSegmentsJson(domain.getSegments() == null
            ? null
            : objectMapper.writeValueAsString(domain.getSegments()));
    entity.setContentBlocksJson(domain.getContentBlocks() == null
            ? null
            : objectMapper.writeValueAsString(domain.getContentBlocks()));
    // size guard:超 256KB 截断 + 标记
    enforceSizeLimit(entity);
    messageMapper.insert(entity);
    return mapper.toDomain(entity);
}

public Message findByNum(String num) {
    MessageEntity entity = messageMapper.selectByNum(num);
    if (entity == null) return null;
    Message domain = mapper.toDomain(entity);
    if (entity.getSegmentsJson() != null) {
        domain.setSegments(objectMapper.readValue(
                entity.getSegmentsJson(),
                new TypeReference<List<AssistantSegment>>() {}));
    }
    // contentBlocks 通常不需要给 FE,内部要用再读
    return domain;
}
```

**Repository 必须只依赖 mapper + ObjectMapper,不依赖其他 Bean**(项目规约,见 [feedback_layer_io_types](../../../../../../.claude/projects/-Users-garry-wang1----projects-DJWork/memory/feedback_layer_io_types.md))。

## 9. 边界 / 限制

### 9.1 byte 限制

- 单字段 `segments_json` / `content_blocks_json` 上限 **256KB**(与 `DebugInvokeStreamService.CONTENT_LIMIT` 对齐)
- 单段 `ToolUse.output` 上限 **64KB**(大代码 / 大日志的典型上限)
- 超限策略:
  - `output` 超 64KB → 截断为前 60KB + 标记 `truncated: true`,FE 卡片底部显示"已截断,完整结果见 trace ID xxx"
  - 整体 `segments_json` 超 256KB → 从尾部 `tool_use.output` 起循环砍 50%,直到达标;无 output 可砍则砍最早的整段
- 截断标记由 BE 写入,FE 仅展示

### 9.2 类型对齐与兼容

- Java `AssistantSegment` 的 `kind` 字段必须与 FE TS 一致(`"thinking"` / `"text"` / `"tool_use"`,**snake_case**)
- 后续协议升级(加 `kind: "image"` 等)走"前向兼容":FE 遇到未知 kind 不报错,silently skip + 控制台 warn
- `latencyMs` 用 `Integer`(可空),旧消息或异常时为 null
- `startedAt` 用 ISO 8601 字符串(`Instant.toString()`),与 FE 一致

### 9.3 用户隐私 / 敏感数据

- 工具 input/output 可能含 Token / Cookie / 内部地址;持久化前**不脱敏**(调试台本就是看原始的)
- 但 `content_blocks_json` 不返 FE,降低意外暴露面;若评测 / BI 需要,走专用脱敏导出脚本

### 9.4 性能

- 写:每条 assistant 消息多 2 个 JSON 字段序列化,~5ms,可忽略
- 读:历史消息列表查询不变(LIMIT 50);单条多 2 个 JSON 列 + 反序列化,典型 ~3KB,可忽略
- 担心 N+1:`getMessages` 一次 select 全部带回,反序列化在应用层 batch 做

## 12. 风险与回退

### 12.1 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| AgentScope SDK 版本升级,PostReasoning 累积语义变 | 段重复 / 段丢失 | 单测覆盖典型流序列,SDK 升级时跑回归;`SegmentAccumulator.handleReasoning` 内做 isLast 判定 |
| segments_json 超 256KB 截断后用户抱怨"看不全" | 调试体验差 | 截断阈值放宽到 1MB(单字段 LONGTEXT 上限远高于此),或对超大段做单独存对象存储 + ref |
| 旧消息无 segments_json 在 FE 视觉断层 | UX 不一致 | 显式给降级路径加"历史会话(旧版协议)"提示标签,引导新发消息 |
| Jackson 多态反序列化失败(kind 不识别) | 单条历史消息渲染失败 | Repository 反序列化包裹 try-catch,失败时记 warn 并返 segments=null,FE 自动降级 |

### 12.2 回退

- 代码层:`AgentInvokeService` 改回直接传 null/getTextContent,2 行代码
- DB 层:**字段保留**(不要 DROP COLUMN,数据保留备用);FE 切回旧分支即可
- 整个改动是**纯加列 + 纯添加渲染分支**,无破坏性变更,回退成本低
