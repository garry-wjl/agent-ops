# 2026-09-19_Agent 内嵌沙箱规格与去热池-技术方案

> 状态：已定稿（产品确认 2026-09-19）  
> 部署架构：**不变**，无新增部署组件。

## 1. 目标与范围

### 1.1 目标

1. **去掉热池**：不再预创建 IDLE、claim 复用、补池；会话工作空间（PVC）与热池互斥的问题一并消失。
2. **沙箱资产 = 规格元数据**：创建/更新沙箱资产时不调用 OpenSandbox 起容器；真正起容器仅在 **创建会话时的 prewarm**（保留）及运行时 `ensureBound`。
3. **Agent 编辑页内嵌维护沙箱规格**；数据仍落沙箱表，`ConfigSnapshot.sandboxRef` 指向资产。
4. **严格 1 Agent : 1 沙箱资产（当前草稿/在线规格）**，禁止共享。
5. **出新草稿版本时复制沙箱资产**；草稿内编辑改「该草稿绑定的那份」。
6. **沙箱管理页只读**（展示/排查）；写入口收敛到 Agent 编辑。

### 1.2 不在本期

- OpenSandbox Pool CR / `poolRef`
- 多 Agent 共用规格
- 按 Agent 拆 PVC（仍用平台共享 PVC + session `subPath`）

### 1.3 产品共识摘要

| # | 决策 |
|---|------|
| 1 | 禁止共享 |
| 2 | 新版本复制新沙箱资产 |
| 3 | 资产只存信息，会话时再起真容器 |
| 4 | 建会话异步 prewarm：**保留** |
| 5 | 沙箱管理：**只读** |
| 6 | 草稿：改当前草稿绑定的沙箱；发布：带上已复制的 ref |

## 2. 架构设计

### 2.1 应用架构

```
Agent 编辑保存
  → AgentCommandService
      → SandboxSpecService.ensureExclusiveForAgent(...)  // 创建或更新元数据资产，状态 ONLINE
      → ConfigSnapshot.sandboxRef = sandbox.num

Agent createVersion
  → 复制当前快照中的 sandbox 资产 → 新 num
  → 草稿 ConfigSnapshot.sandboxRef = 新 num

Session.create
  → @Async SandboxSessionPrewarmService.prewarmIfNeeded
      → SandboxPoolService.ensureBound(..., agentNum)  // 按会话 create + PVC subPath

沙箱管理 UI
  → 仅 Query API（列表/详情）
```

| 层 | 领域 | 包 | 职责 |
|----|------|-----|------|
| client | sandbox / agent | `...client.sandbox` / `...client.agent` | 沙箱规格 DTO；Agent 入参嵌入 `SandboxSpecParam` |
| domain | sandbox | `...domain.sandbox` | 资产聚合去掉热池语义；ONLINE=规格可用 |
| infra | sandbox | `...infra.sandbox` | Entity 增 `owner_agent_num`；Flyway |
| application | sandbox / agent | `...application.sandbox` / `agent` | Spec 保证 1:1；submit 不再 provision 容器；Agent 编排复制 |
| adapter | sandbox / agent | `...adapter.sandbox` | 写接口对前台禁用或仅内部；FE Agent 编辑 |

## 4. 领域设计（sandbox / agent）

### 4.1 Sandbox 模型变更

| 字段 | 变更 |
|------|------|
| `poolEnabled` / `poolSize` | 废弃：写死 false / 忽略；库列可保留兼容，API/UI 去掉 |
| `ownerAgentNum` | **新增**：归属 Agent；同 workspace 内一 Agent 当前「可写」资产由此约束 |
| `sandboxInstanceId` | 资产级代表实例废弃：不再在 online 时写入；会话实例只在 `sandbox_runtime_instance` |
| `status` | `ONLINE` = 规格可用，可被会话引用；不再表示「已有常驻容器」 |

### 4.2 领域规则

1. 创建/更新资产 **禁止** 调 `SandboxContainerGateway.create`。
2. `ownerAgentNum` 非空；禁止把已归属 A 的资产绑到 B。
3. `submit`：直接进入 ONLINE（或创建时即 ONLINE），**不**发「去起容器」的供给任务。
4. `SandboxRunner.provision`：改为 no-op 上线或删除对「预创建」的依赖。
5. `ensureBound`：会话级 create；`isolatesWorkspaceBySession` 时带 PVC subPath。
6. 热池：`provisionAsset` 不预创建；`replenish` / release-to-idle 删除或短路；释放会话后 **销毁** 实例（已有隔离路径）。

### 4.3 Agent 规则

1. 保存草稿/创建：若启用沙箱，upsert 独占资产并写 `sandboxRef`。
2. `createVersion`：若快照含 `sandboxRef`，**深拷贝**沙箱行（新 num、同规格、`ownerAgentNum=本 Agent`），草稿快照改新 ref。
3. `publish`：不另拷贝（草稿已有独立资产）。
4. 校验：`sandboxRef` 必须 `ownerAgentNum == agentNum` 且 ONLINE。

## 5. 数据与迁移

`V48__sandbox_owner_agent.sql`（示意）：

```sql
ALTER TABLE sandbox
  ADD COLUMN owner_agent_num VARCHAR(64) NULL COMMENT '归属 Agent，禁止共享' AFTER workspace_num;

CREATE UNIQUE INDEX uk_sandbox_owner_agent
  ON sandbox (workspace_num, owner_agent_num, deleted);
-- 注意：一 Agent 多历史沙箱（旧版本）会冲突；改为非唯一 + 应用层「当前草稿/在线」约束，
-- 或 uk 仅约束 status=ONLINE 的生成列。推荐：不加强唯一，应用层保证「同一 Agent 同时可写一份」；
-- 历史版本沙箱 owner 相同但 ref 不同，允许多行。
```

**最终采用**：`owner_agent_num` 可空（存量）→ 回填；**无** DB 唯一（因多版本多行）；应用层：

- 绑定校验 owner；
- 从 Agent 写入口创建时强制 owner；
- 沙箱管理写 API 关闭。

存量：`pool_enabled=true` 的 IDLE 实例由一次性清理/对账杀掉；`pool_enabled` 置 false。

## 6. API 契约

### 6.1 Agent

`AgentCreateParam` / 草稿编辑增加可选：

```json
"sandboxSpec": {
  "enabled": true,
  "name": "可选，默认 agent-{num}-sbx",
  "cpu": 1.0,
  "memoryMb": 2048,
  "aliveMinutes": 10,
  "maxConcurrent": 8,
  "sessionIdleTtlMinutes": 30
}
```

- `enabled=false`：清空 `sandboxRef`（不删历史资产，仅解绑当前快照）。
- `enabled=true`：无 ref 则创建 ONLINE 资产；有 ref 且 owner 匹配则更新规格。

### 6.2 Sandbox 管理

- Query：保留。
- Command（create/update/delete/submit/offline/reonline）：**对管理端 UI 下线**；后端可保留给迁移/管理员或直接返回业务错误「请在 Agent 编辑中维护」。

## 7. 前端

1. **Agent 编辑**：`ToolsContextSection` 沙箱 Tab 由「下拉选 ONLINE」改为规格表单（启用开关 + cpu/内存/TTL/并发）；保存带 `sandboxSpec`。
2. **沙箱管理**：去掉新建/编辑/提交/上下线/删除按钮；保留列表与详情只读；文案提示「请在 Agent 中配置」。
3. **类型**：`types/sandbox.ts` 隐藏 pool 字段展示。

---

## 8. 实现顺序

1. Flyway + Entity `ownerAgentNum`；pool API/UI 屏蔽。
2. `SandboxCommandService` / `SandboxRunner` / `SandboxPoolService`：去预创建；submit→ONLINE；释放销毁。
3. `SandboxSpecService` + AgentCommandService 接入创建/更新/createVersion 复制。
4. FE Agent 内嵌 + 沙箱管理只读。
5. 单测 + 推送。

---

## 9. 测试要点

- 创建 Agent+sandboxSpec → 资产 ONLINE、无 OpenSandbox create。
- 建会话 → prewarm → 有 runtime instance +（若 OSS 开）PVC volume。
- createVersion → 新 sandboxRef ≠ 旧；改草稿规格不影响已发布版本 ref 指向的资产。
- 两 Agent 不能绑同一 sandboxNum。
- 沙箱管理无写按钮；写 API 拒绝或 403。
