## 1. 目标与范围

### 1.1 目标

将现有 ProLayout **侧栏布局**（`layout="side"`）升级为 **顶栏 + 侧栏混合布局**（`layout="mix"`），把 LOGO、用户信息从侧栏迁移到顶栏，空间级顶栏额外展示空间切换器和面包屑导航。

### 1.2 范围

**本次做**：

- `HomeLayout` 改为 `layout="mix"`：顶栏显示 LOGO + 用户信息，侧栏保留菜单
- `WorkLayout` 改为 `layout="mix"`：顶栏显示 LOGO + 空间切换器 + 面包屑 + 用户信息
- 新增 `HeaderLogo` 组件：顶栏左侧品牌区（两级布局共用）
- 新增 `HeaderNav` 组件：空间级顶栏中间区域（空间切换器 + 面包屑）
- 改造 `WorkspaceSwitcher`：从侧栏顶部组件改为顶栏中间区域组件
- 新增 `HeaderBreadcrumb` 组件：基于 ProLayout 内置面包屑能力定制
- 新增 `HeaderNav.less`：顶栏组件样式

**本次不做**：后端 API 变更、路由表修改、侧栏菜单结构调整、内容区域样式、视觉体系重构、响应式适配、暗黑模式。

## 2. 架构设计

### 2.1 整体方案：ProLayout `layout="mix"` + `headerContentRender`

ProLayout `layout="mix"` 自带顶栏（header）和侧栏（sider）。关键问题是如何在顶栏中间区域注入自定义内容（空间切换器 + 面包屑）。

**方案选择**：使用 `headerContentRender` 在顶栏中间区域注入自定义 React 元素。

```
┌─────────────────────────────────────────────────┐
│ ProLayout Header (mix 模式自带)                  │
│ ┌─────────┬──────────────────────┬────────────┐  │
│ │ header  │ headerContentRender  │ avatarProps│  │
│ │ Logo    │ 自定义内容(ReactNode) │ 用户信息    │  │
│ └─────────┴──────────────────────┴────────────┘  │
├──────────┬───────────────────────────────────────┤
│          │                                       │
│ Sider    │ Content                               │
│ 侧栏菜单 │ 内容区                                │
└──────────┴───────────────────────────────────────┘
```

**为什么选 `headerContentRender` 而非全自定义顶栏**：
- ProLayout mix 模式已处理了顶栏固定（fixedHeader）、侧栏联动、响应式等复杂逻辑
- `headerContentRender` 在 ProLayout 3.x 中返回 `ReactNode`，直接插入顶栏中间区域
- 保持与 ProLayout 主题体系一致（`navTheme`、`token` 等）

### 2.2 组件结构

```
src/layouts/
├── HomeLayout.tsx          # 平台级布局（顶栏：LOGO + 空 + 用户信息）
├── WorkLayout.tsx          # 空间级布局（顶栏：LOGO + 空间切换器+面包屑 + 用户信息）
├── avatar.tsx              # 用户信息构建函数（零改动）
src/components/
├── HeaderLogo.tsx          # 【新增】顶栏左侧品牌 LOGO 区域
├── HeaderNav.tsx           # 【新增】空间级顶栏中间区域组合组件
├── HeaderBreadcrumb.tsx    # 【新增】面包屑组件（从路由 name 派生）
├── WorkspaceSwitcher.tsx   # 【改造】空间切换器（从侧栏顶部 → 顶栏中间）
└── WorkspaceSwitcher.less  # 【新增】空间切换器/面包屑样式
```

### 2.3 组件职责矩阵

| 组件 | 归属布局 | 职责 | 依赖 |
| --- | --- | --- | --- |
| `HeaderLogo` | 两级共用 | 渲染 🛰️ + "AgentOps" 品牌名；点击跳转行为 | `useNavigate`, `APP_BRAND` |
| `HeaderNav` | 仅空间级 | 组合 `WorkspaceSwitcher` + `HeaderBreadcrumb` | WorkspaceSwitcher, HeaderBreadcrumb |

| `WorkspaceSwitcher` | 仅空间级 | 空间切换下拉（含返回工作空间）；收起侧栏时隐藏 | workspace store, workspace API |

## 3. 详细设计

### 3.1 `HeaderLogo.tsx`

**功能**：顶栏左侧品牌区，两级布局共用

```tsx
// src/components/HeaderLogo.tsx
import { useNavigate } from 'react-router-dom';
import { APP_BRAND } from '@/layouts/avatar';

interface HeaderLogoProps {
  // 空间级：退出到一级门户；平台级：跳到 /workbench
  variant: 'platform' | 'workspace';
}

export default function HeaderLogo({ variant }: HeaderLogoProps) {
  const navigate = useNavigate();
  const handleClick = () => {
    navigate(variant === 'workspace' ? '/workbench' : '/workbench', { replace: true });
  };
  
  return (
    <div className="header-logo" onClick={handleClick}>
      <span className="header-logo-icon">🛰️</span>
      <span className="header-logo-text">{APP_BRAND}</span>
    </div>
  );
}
```

**交互**：点击 → 一律跳转 `/workbench`（空间级等同于退出当前空间）。

### 3.2 `WorkspaceSwitcher.tsx`（改造）

**变更要点**：

1. **移除侧栏相关样式和结构**：原 `ws-breadcrumb` 结构中的「首页」链接不再需要（由 `HeaderLogo` 承担返回功能）
2. **保留核心逻辑**：空间列表查询、切换、URL 同步、`collapsed` 控制
3. **简化输出**：改为纯下拉空间选择器，不再包含面包屑前缀

```tsx
// src/components/WorkspaceSwitcher.tsx (改造后)
// 核心变更：
// - 移除 "首页" 面包屑前缀（HeaderLogo 已承担）
// - collapsed 时隐藏整个组件（而非显示"首页"）
// - 下拉标题改为"切换空间"，底部追加"返回工作空间"入口
// - 保留所有切换/同步/queryClient.invalidateQueries 逻辑
```

**下拉菜单结构**：
```
┌──────────────────────┐
│  切换空间             │  ← group label
│  ✓ AI Coding 组       │  ← 当前项打勾
│  Agent 平台           │
│  流程管理             │
│  ───────────────────  │
│  ← 返回工作空间       │  ← 底部返回入口
└──────────────────────┘
```

**收起侧栏时**：`WorkspaceSwitcher` 隐藏（顶栏不受侧栏宽度影响，但为保持一致性，侧栏收起时顶栏空间切换器也不显示——因为侧栏收起时菜单已不可见，空间切换无意义）。

### 3.3 `HeaderBreadcrumb.tsx`

**功能**：从路由配置 `name` 字段派生面包屑

```tsx
// src/components/HeaderBreadcrumb.tsx
// 数据来源：
// 1. 从 WorkLayout 的 route.routes 中匹配当前 pathname
// 2. 提取匹配到的路由 name（如 "Agent 管理"）
// 3. 对 editor/detail/compare 等路径，追加实体名称
//
// 面包屑格式：
// - 列表页：模块名（如 "Agent 管理"）
// - 新建页：模块名 › 新建（如 "Agent 管理 › 新建"）
// - 编辑页：模块名 › 实体名（如 "Agent 管理 › 客服助手 Agent"）
```

**实体名称获取策略**：

由于面包屑需要在页面数据加载后才能显示实体名称，采用以下策略：

1. **默认面包屑**：仅展示模块名（从路由 `name` 获取），无实体名称部分
2. **实体名称注入**：各页面通过 `useBreadcrumbName(name: string)` 钩子主动注入实体名称到全局 store 或 context
3. **面包屑组件**：从 store 读取当前页面的实体名称，如果有则追加到面包屑

```tsx
// src/hooks/useBreadcrumbName.ts
// 简易方案：使用 zustand store 存储当前面包屑名称
// 页面组件调用：useBreadcrumbName(agentData.name)
// HeaderBreadcrumb 读取：useBreadcrumbStore(s => s.currentName)
```

**为什么不用 ProLayout 自带面包屑**：
- ProLayout `layout="mix"` 自带面包屑能力，但它是从 `route.routes` 的层级关系自动生成的
- 当前的路由是扁平的（`/agent/manage`, `/agent/manage/editor/:num`），没有层级嵌套
- 自定义面包屑可以更精确地控制展示内容和实体名称注入
- **但 ProLayout 自带面包屑可以用作兜底**：在 `HeaderNav` 中用 `headerContentRender` 插入自定义面包屑，覆盖 ProLayout 默认面包屑

### 3.4 `HeaderNav.tsx`

**功能**：空间级顶栏中间区域组合组件

```tsx
// src/components/HeaderNav.tsx
// 组合：WorkspaceSwitcher + 分隔符 › + HeaderBreadcrumb
// 侧栏收起时隐藏整个 HeaderNav

export default function HeaderNav({ collapsed }: { collapsed?: boolean }) {
  if (collapsed) return null;
  
  return (
    <div className="header-nav">
      <WorkspaceSwitcher collapsed={false} />
      <span className="header-nav-sep">›</span>
      <HeaderBreadcrumb />
    </div>
  );
}
```

### 3.7 `avatar.tsx` 适配

`buildAvatarProps` 返回的 `render` 函数当前是为 ProLayout `avatarProps` 设计的——渲染侧栏底部的用户信息卡片（带头像、名称、版本号、退出菜单）。

在 `layout="mix"` 模式下，`avatarProps` 渲染的是**顶栏右侧**的用户头像区域。需要调整 `render` 的输出：

```tsx
// avatar.tsx 变更：
// - 保留 buildAvatarProps 函数签名
// - render 函数改为渲染顶栏用户头像（圆形头像 + 用户名）
// - 移除侧栏底部样式（padding-top, border-top, flex column）
// - 保留 Dropdown 退出登录逻辑
```

**方案 A：调整 `buildAvatarProps` 内部 `render`**

改动 `render` 为顶栏适配的输出（圆形头像 + 用户名，点击展开下拉退出）。

**方案 B：新增 `buildHeaderAvatarProps` 函数**

不改动现有的 `buildAvatarProps`，新增一个专门给顶栏用的构建函数。

**推荐方案 A**：因为 HomeLayout/WorkLayout 改造后，`avatarProps` 只在顶栏使用，侧栏底部不再需要用户信息。保持单一入口。

## 5. ProLayout mix 模式适配要点

### 5.1 `headerContentRender` 返回值处理

ProLayout 3.x `headerContentRender` 的签名是 `(props: HeaderContentRenderProps) => ReactNode`。

```tsx
// WorkLayout 中的用法
headerContentRender={(props) => (
  <HeaderNav collapsed={collapsed} />
)}
```

如果 ProLayout 版本中 `headerContentRender` 不可用或不生效，兜底方案是：

**兜底方案**：使用 `menuHeaderRender` 的返回值改为顶栏内容（在 ProLayout 外部套一层自定义 header div），但会失去 ProLayout 顶栏的原生能力（如 fixedHeader、主题联动等）。**优先尝试 `headerContentRender`，不生效再切兜底。**

### 5.2 `layout="mix"` 对侧栏的影响

- mix 模式下，ProLayout 会自动在顶栏生成一级菜单（如果 `route.routes` 有嵌套结构）
- 当前 `WorkLayout` 的 `route.routes` 使用的是 group 模式（`{ path: "/group-runtime", name: "Agent 与沙箱", routes: [...] }`）
- **需要在 mix 模式下隐藏顶栏一级菜单**：通过 `menu={{ type: "group" }}` 或在 `route.routes` 中设置 `hideInMenu: true` 给 group 节点

### 5.3 面包屑行为

`layout="mix"` 自带面包屑组件，可以通过 `breadcrumbRender` 定制。但我们选择用自定义 `HeaderBreadcrumb` 覆盖默认面包屑：

```tsx
// 通过 breadcrumbRender: false 或 breadcrumb={false} 禁用 ProLayout 自带面包屑
// 在 headerContentRender 中渲染自定义 HeaderBreadcrumb
```

### 5.4 `avatarProps` 位置

mix 模式下，`avatarProps` 自动渲染到顶栏最右侧，无需额外处理。`render` 函数返回的内容会被 ProLayout 包装为标准头像区域。

## 6. 面包屑数据流

```
页面路由 (/agent/manage/editor/:num)
  ↓
HeaderBreadcrumb 从 useLocation 获取 pathname
  ↓
匹配 route.routes 中的路由定义，获取模块名 "Agent 管理"
  ↓
检查 breadcrumbStore 中是否有当前页面的实体名称
  ↓ (有)
渲染 "Agent 管理 › 客服助手 Agent"
  ↓ (无)
渲染 "Agent 管理"

实体名称注入流程：
页面组件获取数据 → useBreadcrumbName(data.name) → 写入 breadcrumbStore
  ↓
HeaderBreadcrumb 读取 breadcrumbStore → 更新面包屑
```

### 6.1 `breadcrumbStore.ts`（新增）

```ts
// src/stores/breadcrumb.ts
import { create } from 'zustand';

interface BreadcrumbState {
  moduleName: string;    // 模块名（从路由 name 获取）
  entityName?: string;   // 实体名（从页面数据注入）
  setModule: (name: string) => void;
  setEntity: (name?: string) => void;
  reset: () => void;
}

export const useBreadcrumbStore = create<BreadcrumbState>((set) => ({
  moduleName: '',
  entityName: undefined,
  setModule: (name) => set({ moduleName: name, entityName: undefined }),
  setEntity: (name) => set({ entityName: name }),
  reset: () => set({ moduleName: '', entityName: undefined }),
}));
```

### 6.2 `useBreadcrumbName` hook（新增）

```tsx
// src/hooks/useBreadcrumbName.ts
import { useEffect } from 'react';
import { useBreadcrumbStore } from '@/stores/breadcrumb';

export function useBreadcrumbName(name: string) {
  const setEntity = useBreadcrumbStore((s) => s.setEntity);
  useEffect(() => {
    setEntity(name);
    return () => setEntity(undefined);
  }, [name, setEntity]);
}
```

**使用示例**：
```tsx
// Agent 编辑页
function AgentEditor() {
  const { data: agent } = useAgentQuery(num);
  useBreadcrumbName(agent?.name ?? '');
  // ... 渲染编辑表单
}
```

## 7. 路由与面包屑映射表

基于当前 `router/index.tsx` 的路由，面包屑映射关系：

| 路由路径 | 模块名（来自 route.routes） | 面包屑展示 | 实体名注入 |
| --- | --- | --- | --- |
| `/agent/manage` | Agent 管理 | `Agent 管理` | 无 |
| `/agent/manage/editor/:num` | Agent 管理 | `Agent 管理 › 新建` | 固定"新建" |
| `/agent/manage/detail/:num` | Agent 管理 | `Agent 管理 › xxx` | `agent.name` |

## 9. 风险与缓解

| 风险 | 影响 | 缓解措施 |
| --- | --- | --- |
| `headerContentRender` API 在 ProComponents 3.1.12-0 中行为不符预期 | 顶栏中间区域无法插入自定义内容 | 兜底：在 ProLayout 外部套一层自定义 header div，`layout="side"` + `fixedHeader` 模拟 mix 效果 |
| mix 模式下 ProLayout 自动生成顶栏一级菜单 | 顶栏出现多余的菜单项 | `menu={{ type: "group" }}` + 在路由配置中给 group 节点加 `hideInMenu: true` |
| ProLayout 自带面包屑与自定义面包屑冲突 | 显示两套面包屑 | `breadcrumb={false}` 禁用 ProLayout 自带面包屑 |
| 侧栏收起时顶栏空间切换器/面包屑的显示行为 | 视觉不协调 | `collapsed` 传递给 `HeaderNav`，收起时返回 `null` |
| 面包屑实体名称在页面数据加载前为空 | 面包屑闪烁或显示不完整 | 实体名称加载前只显示模块名，数据加载后通过 zustand 追加实体名 |
| `avatarProps` 的 `render` 在 mix 模式下被 ProLayout 包装 | 自定义样式被覆盖 | 在 `render` 返回纯头像元素（不带 Dropdown 容器），让 ProLayout 处理 Dropdown 行为 |
