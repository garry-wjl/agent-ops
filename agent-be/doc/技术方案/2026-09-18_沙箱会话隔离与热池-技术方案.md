# 2026-09-18_沙箱会话隔离与热池-技术方案

> 分支：`feature-20260912-harness-agent`（或后续 `feature-*-sandbox-pool`）  
> 共识来源：PaaS 多应用接入场景下，默认「规格复用 + 会话级容器」；可选热池加速；本地/单测 Mock OpenSandbox。

## 1. 目标与范围

### 1.1 目标

1. **会话级强隔离**：同一沙箱资产（规格）下，不同会话绑定不同 OpenSandbox 容器实例。  
2. **可选热池**：沙箱资产上配置「启用池 / 常驻数（默认 1）」；开池后维持水位，会话 claim，池空则慢路径 create 并异步补池。  
3. **会话预热 + 会话内复用 + 结束短 TTL**：创建会话异步预热；多轮复用同一 `instanceId`；会话空闲超过 TTL 后回收（回池或销毁）。  
4. **配置落点**：沙箱管理资产（非 Agent）；Agent 仍只绑 `sandboxRef`。  
5. **可测性**：抽象容器网关；`sandbox.mock=true` 或单测用 Mock，不依赖真实 OpenSandbox。

### 1.2 不在本期

- OSS workspace 快照 / Harness RemoteSnapshot（另案）。  
- 按用户 USER 级容器（默认 SESSION）。  
- 脏容器回炉清洗（TTL 到期默认 **kill**；开池时仅当空闲数 &lt; poolSize 才保留为 IDLE）。

### 1.3 部署架构

**部署架构不变**，无新增部署组件；复用现有 be/fe 与 OpenSandbox 网关。新增配置项：`sandbox.mock`（本地/测试）。

## 2. 应用架构

### 2.1 核心流程

```text
沙箱资产 ONLINE（规格就绪）
        │
        ├─ pool_enabled=true ──submit 供给──► 预创建 pool_size 台 IDLE 实例入池
        │
        └─ pool_enabled=false ──submit──────► 不预创建容器，仅 ONLINE
                 │
创建会话 / 首次 invoke
                 │
         SandboxPoolService.ensureBound(sandboxNum, sessionNum)
                 │
         已有绑定? ──是──► 返回 instanceId（会话内复用）
                 │否
         从 IDLE claim? ──是──► BOUND + 绑定 sessionNum
                 │否
         活实例 < max_concurrent? ──是──► create + BOUND
                 │否
                 └── 失败：资源不足
                 │
         （开池）异步 replenish 至 pool_size
                 │
会话结束 / 空闲 TTL
                 │
         解绑 → 若开池且 IDLE 数 < pool_size → IDLE；否则 kill
```

### 2.2 代码结构

| 层 | 领域 | 包 | 职责 |
|----|------|-----|------|
| client | sandbox | `...client.sandbox.*` | VO/DTO/Param 增加池字段 |
| domain | sandbox | `...domain.sandbox` | 资产池配置字段；运行时实例聚合/仓储接口 |
| domain | sandbox | `...domain.sandbox.gateway` | `SandboxContainerGateway` 抽象 create/kill/isAlive |
| infra | sandbox | `...infra.sandbox` | Entity/Mapper/Flyway；Gateway 真实现 + Mock |
| application | sandbox | `...application.sandbox.pool` | `SandboxPoolService` claim/release/replenish |
| application | sandbox | `...application.sandbox.runner` | provision 改填池；destroy 杀全部实例 |
| application | session | `...application.session` | createSession 后异步预热 |
| application | agentrunner | `...agentrunner.factory` | 解析 instanceId 改为 pool.ensureBound |
| adapter | sandbox | scheduler | 空闲 TTL 扫描 + 补池 |
| fe | Sandboxes | `SandboxFormDrawer` | 池开关 + 常驻数 |

### 2.3 命令 / 查询

- **命令**：创建/更新沙箱时写入池配置；submit 触发供给；会话创建触发预热；idle TTL 触发回收。  
- **查询**：详情/列表返回池配置；可选返回池水位（IDLE/BOUND 计数）。

## 4. 领域层（sandbox）

### 4.1 资产 Sandbox 新增字段

| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| poolEnabled | boolean | false | 是否启用热池 |
| poolSize | int | 1 | 常驻 IDLE 目标水位；仅 poolEnabled 时有效 |
| maxConcurrent | int | 8 | 该资产最大活实例（IDLE+BOUND）；触顶不可再 create |
| sessionIdleTtlMinutes | int | 10 | 会话无活动后回收等待 |

校验：`poolEnabled=true` 时 `1 ≤ poolSize ≤ maxConcurrent`；`maxConcurrent ≥ 1`。

`sandboxInstanceId`：保留兼容；开池后可指向任意代表实例或置空，**运行时以 runtime 表为准**。

### 4.2 运行时实例 SandboxRuntimeInstance（新）

| 字段 | 说明 |
|------|------|
| num | 业务号 SRI… |
| sandboxNum | 资产 num |
| workspaceNum | 工作空间 |
| opensandboxInstanceId | 远程容器 id |
| status | IDLE / BOUND |
| sessionNum | BOUND 时非空 |
| lastActiveAt | 滑动活跃时间（预热/ invoke 更新） |
| idleSince | 进入 IDLE 或解绑待回收时间 |

### 4.3 网关

`SandboxContainerGateway`：`create(cpu, memoryMb, aliveMinutes)` / `kill` / `isAlive`。  
真实现调现有 OpenSandbox SDK；Mock 实现内存 Map，供本地与单测。

## 6. 应用层要点

1. **SandboxRunner.provision**：读资产池配置 → 开池则循环 create 写入 IDLE → `online`；不开池则直接 `online`（无预创建）。  
2. **SandboxRunner.destroyContainer**：kill 该资产下全部 runtime 实例并清表。  
3. **SandboxPoolService.ensureBound**：会话绑定核心。  
4. **SessionCommandService.createSession**：若 Agent CONFIG 且有 sandboxRef 且资产 ONLINE → `@Async` prewarm(`ensureBound`)。  
5. **AgentRunnerFactory**：`instanceId = pool.ensureBound(ref, sessionNum)`。  
6. **Scheduler**：扫描 BOUND 且 `lastActiveAt` 超时 → release；IDLE 低于水位 → replenish；死亡实例清理。

### 兼容

- 存量 ONLINE 资产：`pool_enabled=false`，行为变为「按会话 create」（与 PaaS 共识一致）；若需旧「全员共用一台」，可后续加 `shareMode`（本期不做）。  
- Harness `OpenSandboxFilesystemSpec` 仍只挂本会话 `instanceId`。
