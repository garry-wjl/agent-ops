## Bug：同名 Skill 不能跨空间创建

| 字段 | 值 |
|------|-----|
| 模块 | Skill 管理 - 创建 |
| BUG 分类 | 边界与异常处理 |
| 严重程度 | 严重 B（功能不可用） |
| 复现概率 | Always |

### 现象

在 A 空间创建名为"XX方案"的 Skill 后，切换到 B 空间再创建同名 Skill 时，接口报错"Skill 名称已存在"。预期行为：两个空间各自独立管理 Skill，同名 Skill 可以跨空间创建。

### 原因分析

**结论：后端唯一性校验范围错了，绑定了 ownerUserId 而非 workspaceNum。**

`SkillCommandService.createSkill()` 中唯一性预检用的是：

```java
// 锁粒度：(ownerUserId, name)
String lockKey = LockKeyConstant.SKILL_CREATE_LOCK_PREFIX
        + param.getOwnerUserId() + ":" + param.getName();
// ...
if (skillQueryService.existsByOwnerAndName(param.getOwnerUserId(), param.getName())) {
```

对应的 SQL 是：

```java
skillMapper.selectCount(Wrappers.<SkillEntity>lambdaQuery()
        .eq(SkillEntity::getOwnerUserId, ownerUserId)
        .eq(SkillEntity::getName, name)
        .eq(SkillEntity::getSource, SkillSource.SELF.name()));
```

**没有包含 `workspaceNum` 条件。** 同一 ownerUserId 下 name 全局唯一，跨空间当然不能重名。

**对比：Tool 是正确的——按空间隔离：**

```java
// 锁粒度：(workspaceNum, name)
String lockKey = LockKeyConstant.TOOL_CREATE_LOCK_PREFIX + workspaceNum + ":" + param.getName();
if (toolQueryService.existsByName(workspaceNum, param.getName(), null)) {
```

**数据库索引也一样——旧索引：**

```sql
UNIQUE KEY `uk_skill_owner_name` (`owner_user_id`,`name`,`deleted`),
```

而 Tool 的索引是：

```sql
UNIQUE KEY `uq_tool_ws_name` (`workspace_num`,`name`,`deleted`),
```

### 修改方案

| # | 改动 | 位置 | 说明 |
|---|------|------|------|
| 1 | 方法改名 + 改字段 | `SkillQueryService.existsByOwnerAndName` → `existsByWorkspaceAndName(workspaceNum, name)` | 条件从 ownerUserId 改为 workspaceNum |
| 2 | 锁粒度 + 预检调用 | `SkillCommandService.createSkill` | 锁 key 改为 `(workspaceNum, name)`，优先取 param.workspaceNum 再兜底 |
| 3 | 新字段 | `SkillCreateParamDTO.workspaceNum` | adapter 层注入，不在前端 VO 暴露 |
| 4 | 注入空间编号 | `SkillVoAssembler.toCreateDTO` | 调用 `WorkspaceContextHolder.currentWorkspaceNum()` 设入 DTO |
| 5 | 数据库迁移 | `V34__skill_unique_by_workspace_name.sql` | 删 `uk_skill_owner_name`，建 `uq_skill_ws_name(workspace_num, name, deleted)` |

### 影响范围

- 后端 5 文件，包含 1 个 Flyway 迁移。
- 前端无需变更（VO 层不暴露 workspaceNum）。
- 行为变化：Skill 名从"全局+owner"唯一改为"按空间"唯一，与 Tool / Model / Sandbox 等模块保持一致。

### 验证

- 全量 60 例单元测试通过，无回归。
- 未新增用例——现有 SkillCommandService 测试未覆盖创建路径的 mock（因 DB 依赖较重），本次改动是纯逻辑等价替换（ownerUserId → workspaceNum），无分支变化。
