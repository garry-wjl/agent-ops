## Bug：API 调用产生的会话不显示在 Agent「会话历史」Tab

| 字段 | 值 |
|------|-----|
| 模块 | 会话（Session）- 会话历史 |
| BUG 分类 | 逻辑错误（过滤条件 + 归属维度设计） |
| 严重程度 | 严重 B（功能不完整，API 会话对管理端不可见） |
| 复现概率 | Always |

### 现象

通过开放接口（OpenAPI，秘钥 Bearer 认证）`POST /api/v1/open/agents/command/invoke` 调用 Agent 产生的会话记录，不出现在管理端 Agent 详情页的「会话历史」Tab 中；而 web 调试台产生的会话正常显示。

### 原因分析

**主根因：会话历史列表按「创建人私有」过滤，把 API 会话排除了。**

「会话历史」Tab 的查询 `SessionQueryService.pageList` 中有一条硬过滤：

```java
LambdaQueryWrapper<SessionEntity> wrapper = new LambdaQueryWrapper<SessionEntity>()
        .eq(SessionEntity::getCreatorUserId, operatorId)   // ← operatorId = 当前登录 web 用户 SSO id
        ...
```

而 API 调用无登录用户，`OpenAgentInvokeService.resolveOperator` 在 operatorId 为空时兜底为字符串 `"system"`，落库时 `creator_user_id = "system"`（或调用方随手传入的任意串）。二者永远不相等，故所有 API 会话被这条等值过滤永久排除。

对比：web 调试台入口 `DebugInvokeController` 传的是 `getCurrentUserId()`（真实登录用户），故能匹配、能显示。

**关键点**：前端 `SessionHistoryTab.tsx` 头部注释已明确「展示该 Agent 的**全部**历史会话」，且请求只带 `agentNum`——即产品意图本就是「Agent 维度的全部会话」，是后端错误地按创建人做了私有化。

**次要问题：API 自动建会话的 `origin` 被误标为 `DEBUG_CONSOLE`。**

`AgentRunnerService.runAgent` 在 `sessionNum` 为空自动新建会话时，`origin` 被硬编码为 `"DEBUG_CONSOLE"`：

```java
if (StrUtil.isBlank(sessionNum)) {
    SessionDTO sessionDTO = sessionCommandService.createSession(agentNum, "", "", operatorId, "DEBUG_CONSOLE");
    ...
}
```

API `invoke` 走该分支时来源被误标，前端来源标签（调试台 / API）显示错乱。

### 修复方案（方案：会话可见性改为 Agent 维度）

将会话归属维度从「创建人私有」调整为「Agent 维度」，与前端既有意图对齐。

1. **`SessionQueryService.pageList`**
   - 去掉 `.eq(creatorUserId, operatorId)`；改为按 `agentNum` 过滤。
   - `agentNum` 变为**必填**（缺省会退化成全量会话查询，导致跨 Agent 泄露），空则抛 `INVALID_PARAM`。
   - 移除已失效的 `operatorId` 入参。

2. **`SessionQueryService.detail` / `listMessages`**
   - 原 `requireOwnedSession` 去掉 `creatorUserId` 归属校验（否则从历史点开 API 会话会误判 403），改为仅校验存在 + 未删除，重命名为 `requireExistingSession`。
   - 移除失效的 `operatorId` 入参。

3. **调用方对齐**
   - `SessionQueryController`（web）：`list/detail/messages` 不再传 `getCurrentUserId()`。
   - `OpenAgentInvokeService` / `OpenAgentController`（open API）：`listSessions/sessionDetail` 不再传 `operatorId`；写接口 `invoke/createSession` 保留 operator 兜底（仍需写 `creator_user_id`）。

4. **`AgentRunnerService.runAgent`（次要 bug）**
   - 新增带 `origin` 的最底层重载；API 入口（4 参重载）传 `"API"`，web 调试入口（5 参重载）传 `"DEBUG_CONSOLE"`，不再硬编码。

### 影响与风险

- **可见性放宽**：会话可见性从「按用户私有」放宽为「按 Agent 共享」——同一控制台内任何登录用户都能看到该 Agent 下所有人（含 API）的会话。这是本方案的固有语义，且与前端注释一致。
- **open API 会话详情**：`sessionDetail` 去掉归属校验后，仅按会话编号取详情（列表接口仍按秘钥归属的 `agentNum` 收敛）。原基于 `operatorId="system"` 的校验本已失效，非本次新增风险。
